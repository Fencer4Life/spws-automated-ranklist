Why this page exists

Purpose

An event's code says three things: who organizes the event, which tournament type its results score as, and how those results reach the ranklist. A bracket's results engine says a fourth: whether the bracket is final yet. Two registries in the code hold these facts, and nothing else states them.

  • python/pipeline/organizers.py holds the organizers on the results route, their route class and the code families of their events.
  • ENGINES in python/pipeline/international_sources.py holds the results engines and whether each one says when a bracket is final.

The tables below repeat both registries for readers. ROUTE.ORG.13 and ENGINE.03 fail when a table and the code disagree. Adding an organizer or an engine starts here (ADR-119).

One question per bracket

When a bracket is final

A run takes only the brackets that are final. A skipped bracket's reason starts with “not final”. Any such skip keeps the event IN_PROGRESS: the daily close leaves it open, and the next ingest reads the bracket again. A multi-day event is therefore ingested several times while it runs, each run adding the brackets that have finished since.

An engine that says when a bracket is final decides for itself. For an engine that says nothing, the reader that asks decides:

Who readsRuleWhy
The live ingest on CERTA bracket is final once its exact content (its SHA-256) was first seen 60 minutes ago or more, or once the event has ended: today in Warsaw is past its end date. A bracket still waiting is skipped as “not final (no finished signal; its content is not yet 60 minutes old)”.A results page changes while a bracket is fenced; content unchanged for an hour has stopped changing. After the end date nothing is still being fenced.
Promote's plan on PRODExactly the brackets the CERT run took, with exactly the content it took.PROD receives what CERT verified, never a newer page.
The daily closeEvery published bracket.It runs only after the end date.

Each sighting is a row of tbl_listing_sighting: the event code, the bracket's key, its content hash, when it was first seen and when it was last seen. A new content hash is a new row, so a bracket that changes starts its hour again. The table has row-level security on and no grant to anon or authenticated. Only service_role writes it, through fn_listing_sighting_record, which keeps the first sighting and returns its time. Nothing deletes a sighting. Only the live ingest writes it, so its rows are CERT's (and LOCAL's), and the PROD seed export never carries it (FINAL.08).

Ingest, promote's plan and the daily close read an event's sources in the same order and classify them source by source, so its schedule hashes the same in all three (FINAL.06, FINAL.07).

Checklist

Adding a results engine

  1. Its reader, dispatched by Fetcher.fetch_event_url_with_skips, with a fixture.
  2. Its Engine entry in ENGINES and its branch in engine_of.
  3. Its answer to the finality question. An engine that says when a bracket is final marks an unfinished bracket skipped with finished false and its state; the route records it as “not final (<engine> shows it <state>)”. An engine that says nothing gets signal false, and the 60-minute rule applies with no further code.
  4. Its row in the engine table above (ENGINE.03) and its pin in ENGINE.01.

Do not confuse these

Sets that look like the registry and are not

  • The minimum-participant routing. PEW, MEW and MSW gate on the EVF minimum; PPW, MPW and PSW on the domestic one; PPS and MPS on 1 (ADR-066). The database holds it per type, and pgTAP SS26.TYPE.02 pins it. check_min_participants in python/scrapers/base.py agrees with it (ROUTE.ORG.10). PSW is international on the route and domestic here, which is why the two sets are kept apart.
  • The types EVF's results API scores. PEW, MEW and MSW: python/tools/evf_event_completeness.py pairs EVF's events with ours by them (ADR-028).
  • Spreadsheet sheet names. The historical seed tools map a sheet (GP1, PP1, EVF1, PS, VFC) to a type and a code prefix. The organizer of the resulting code still comes from the registry, so a sheet the registry does not know reads UNKNOWN and its event is not written.

ROUTE.ORG.06 scans every module under python/ for a prefix match or a hand-written organizer, and names the first two sets above as the only other facts.

Maintenance

Change triggers

Review this page when an organizer, a code family, a tournament type or a results engine is added or changed, when a finality rule or the 60-minute settle time changes, and when any code starts reading an event-code prefix. ROUTE.ORG.13 and ENGINE.03 fail until the tables match the code again.

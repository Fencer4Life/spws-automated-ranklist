Operations · Multi-agent development

Claude and Codex working at the same time

Give each agent its own folder and branch. Let them work simultaneously, then merge their finished work one branch at a time through a clean integration checkout.

macOS + VS CodeSeparate worktreesOne integratorNo shared dirt

The idea in one minute

Three folders, three jobs

A Git worktree is another folder containing the same repository on a different branch. It shares Git history with the other folders, but its checked-out files and uncommitted changes are independent.

Worker 1

Codex worktree

Codex edits and commits only its assigned task on codex/<task>.

Worker 2

Claude worktree

Claude edits and commits only its assigned task on claude/<task>.

Traffic controller

Integration checkout

No feature editing. It reviews, validates and merges one completed worker branch at a time.

The key rule: simultaneous work is safe because Claude and Codex never edit inside the same folder. Their branches meet only after one task is complete.

This is the preferred layout: all three checkouts are direct siblings. The task names are examples. If the original SPWSranklist checkout cannot be made clean, add a fourth sibling named SPWSranklist-integration and register that temporary traffic-control checkout instead.

The folder /private/tmp/claude-501 is Claude Code runtime data—not a Git worktree and not something to open as the repository.

Branch and folder are different things. The branch records commits. The worktree is the physical folder where one agent edits that branch.

One-time setup

Choose and register the integration checkout

Root checkout is clean

Use /Users/aleks/coding/SPWSranklist as the integration checkout. Do not use it for feature editing afterward.

OR

Root contains old or unfamiliar files

Create /Users/aleks/coding/SPWSranklist-integration. This is the safer choice while the old root remains dirty.

Create a dedicated clean integration checkout

cd /Users/aleks/coding/SPWSranklist
git fetch origin main
git worktree add -b integration/main \
  /Users/aleks/coding/SPWSranklist-integration origin/main

cd /Users/aleks/coding/SPWSranklist-integration
bash scripts/install-agent-worktree-guards.sh --integration

The installer records this folder as the only checkout allowed to update remote main. The tracked pre-push hook blocks accidental worker-to-main pushes.

The remaining examples use the preferred root integration path. If you registered SPWSranklist-integration instead, substitute that path wherever an integration checkout is shown.

Do not register a dirty checkout. Registration, worker creation and integration deliberately fail when the integration folder has modified or untracked files.

At the start of two tasks

Create one worker for Claude and one for Codex

Run these commands from the registered integration checkout. Use task names that say what each agent owns.

cd /Users/aleks/coding/SPWSranklist

bash scripts/start-agent-worktree.sh codex ftl-manual-test

bash scripts/start-agent-worktree.sh claude calendar-docs

Both branches start from the same current origin/main. The script creates direct siblings under /Users/aleks/coding and refuses duplicate branch names or existing folder paths.

Before prompting either agent

Assign tasks with explicit file ownership

Separate folders prevent accidental staging, but two branches can still make conflicting edits to the same source file. Give each agent a bounded outcome and anticipated paths.

Good split

  • Codex: manual-trigger E2E tests and related test documentation.
  • Claude: calendar tutorial copy and screenshots.
  • Little or no expected file overlap.

Risky split

  • Both agents redesign EventManager.svelte.
  • Both agents edit the same migration.
  • “Improve anything you find” without path boundaries.

If both tasks require the same core file, work sequentially. Finish and integrate the first task, then create or rebase the second task from the new origin/main.

Normal working day

How simultaneous work actually proceeds

09:00
The integrator creates both worker branches from the same origin/main.
09:05
Codex works in the Codex folder while Claude works in the Claude folder. Neither sees the other's uncommitted files.
10:15
Codex finishes first, runs its checks and commits to codex/ftl-manual-test.
10:20
The integrator merges Codex, validates the combined tree and pushes HEAD:main.
10:45
Claude finishes and commits. Because main moved, Claude rebases its branch onto the new origin/main.
11:00
The integrator merges Claude, validates again and pushes the second integration.
origin/main ───────┬──────── codex/ftl-manual-test ── commit ──┐
                  │                                             │
                  └──────── claude/calendar-docs ───── commit ──┼─ rebase after first merge
                                                                │
clean integration checkout ◀── merge one branch ─ validate ─ push HEAD:main
                              then repeat for the second branch

Inside each worker

Finish and commit the assigned task

  1. Check scope. Run git status --short; every path must belong to this task.
  2. Run narrow validation. Test the changed behavior first, then run applicable repository gates.
  3. Refresh Graphify. Run scripts/refresh-graph.sh and follow its exit-code instructions.
  4. Stage explicit paths. Never use broad staging when unfamiliar files are present.
  5. Commit only to the worker branch. Keep the branch local until its base is final unless a remote review branch is explicitly needed. A worker never pushes remote main.
git status --short
# Run task-specific tests and documentation gates.
bash scripts/refresh-graph.sh
git add path/owned-by-this-task another/owned-path
git diff --cached --check
git commit -m "test: cover FTL manual trigger end to end"

Only in the clean integration checkout

Integrate one completed branch

  1. Confirm the worker has committed everything and its worktree is clean.
  2. Confirm the integration checkout is clean and exactly synchronized with origin/main.
  3. Run the integration helper for one branch. It reviews the diff and creates a local merge; it does not push.
  4. Run the checks appropriate to the merged change and inspect the merge.
  5. Push the current integration branch to remote main.
cd /Users/aleks/coding/SPWSranklist

bash scripts/integrate-agent-branch.sh codex/ftl-manual-test
# Run applicable validation here.
git status --short
git log -3 --oneline --decorate
git push origin HEAD:main
The helper intentionally stops before pushing. This creates a human-visible checkpoint between “the branch merged locally” and “main changed for everyone.”

After the first task reaches main

Rebase the second worker before integration

The second agent may have worked simultaneously from the older base. After committing its own work, it must replay that work on the newly updated origin/main.

cd /Users/aleks/coding/SPWSranklist-claude-calendar-docs
git status --short                 # must be clean
git fetch origin main
git rebase origin/main
# Resolve and test any conflict here, in Claude's own worktree.
git push -u origin claude/calendar-docs  # only if not previously published

Never force-push or rewrite a published branch. The integration helper can merge the local worker branch, so remote publication is optional. If a task branch was already published before main moved, stop and coordinate rather than rewriting shared history.

Once rebased and validated, integrate it from the clean integration checkout with scripts/integrate-agent-branch.sh claude/calendar-docs.

Local generated state

Give each worker its own Graphify cache

graphify-out/ is ignored by Git, so it does not appear automatically in a new worktree. Seed each worker from a refreshed integration cache instead of running two full semantic builds.

# Run from a newly created worker.
mkdir -p graphify-out
cp /Users/aleks/coding/SPWSranklist/graphify-out/graph.json graphify-out/
cp /Users/aleks/coding/SPWSranklist/graphify-out/manifest.json graphify-out/
cp /Users/aleks/coding/SPWSranklist/graphify-out/.graphify_labels.json graphify-out/
cp /Users/aleks/coding/SPWSranklist/graphify-out/GRAPH_REPORT.md graphify-out/

These are portable baseline files. Do not copy .graphify_root, .graphify_python, logs, cost history or .DS_Store. Each worker refreshes its own cache for its branch; agents must not write to one shared live graphify-out/ simultaneously.

Keep beside your terminal

Three short checklists

Start a task

  • Integration checkout clean
  • origin/main fetched
  • Unique task branch
  • Separate worker folder
  • Explicit path ownership

Finish a worker

  • Status contains task paths only
  • Tests and docs gates run
  • Graphify refreshed
  • Explicit staging reviewed
  • Worker branch committed

Integrate

  • One branch at a time
  • Integration checkout clean
  • Branch based on current main
  • Merged tree validated
  • Push HEAD:main only

When uncertain

  • Stop before destructive Git
  • Preserve unfamiliar files
  • Ask who owns the paths
  • Move conflict resolution to worker
  • Do not improvise on main

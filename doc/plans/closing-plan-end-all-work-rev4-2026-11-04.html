02 · The 403 · your questions: “did you forget the session token?” and “what is this 403?”

The session was used. FTL refused the request anyway.

Evidence that the stored session was used. CERT’s ledger for 4 Nov: 28 requests, 1 sign-in, the IMSW run’s. The Liège run drew 1 request and no sign-in; its last line says “FTL today: 28/120 requests, 1/2 sign-ins”. The client’s code takes the stored session when it holds none (store.get(), then client.cookies.set("connect.sid", …), python/scrapers/ftl_auth.py:378–384), and signs in only when there is none. So the request went out with the cookie the IMSW run stored at 18:57 UTC, under the name SPWS-ranklist/1.0, and FTL answered 403 (international_sources._ftl_schedule → raise_for_status). The stored session is still on CERT: only a redirect to the login page drops it, and a 403 is not one.

What is not known. The response body. The client keeps nothing of a refused response, and no run row opened (a read failure opens none), so the alert carries the status and the URL only.

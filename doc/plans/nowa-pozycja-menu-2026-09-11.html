3 · What “atomic” has to mean for this path

Your instinct is right, and these are the constraints the pipeline actually imposes:

Hard requirements
  • One file, nothing fetched. Inline every style and script; embed images as data: URIs, as the calculator does with the SPWS logo. The file bypasses the bundler, so a relative <script src> or image path would have to be published separately and would be easy to break.
  • No 127.0.0.1, no service_role, no supabase-demo. The release job greps the whole of frontend/dist/ for these three strings and fails the release if it finds any. This is a guard you benefit from, but it does mean a file carrying a LOCAL URL or a service key cannot ship.
  • The filename becomes a public URL. Lowercase, ASCII, hyphenated, and chosen once — renaming it later breaks any link already shared with fencers or pasted into WordPress.
  • It is public. Pages serves it to anyone with the address. Add <meta name="robots" content="noindex, nofollow"> if it should stay out of search results, as the calculator does.
  • Bilingual, if it reaches fencers. The drawer passes the ranking's active locale as ?lang=pl / ?lang=en. The calculator reads that parameter and switches itself. If your page is single-language, the link simply should not carry the parameter.

Two things the file will not get, and you should decide knowingly: it is outside the build, so no type checking and no minification cover it, and npm run check will not see it.

4 · The one open item — ADR-085 §2

Needs your decision before I write code

ADR-085, signed off 15 August 2026, established this publication path for the calculator and then closed it explicitly. Section 2 is titled “This is an exception, not a pattern” and states that no other static page is expected to be published this way, that the decision establishes no rule for future tools, and that any further standalone page requires its own decision — with the default routes being a view inside the application, or the register.html custom-element mechanism.

Your new page is precisely that “further standalone page”. The code change is small; the governance step is the real work, and skipping it would leave the ADR corpus stating something that is no longer true.

5 · Questions for you

Q1 — How should the second static page be recorded?

OptionWhat it means
A — Amend ADR-085 Rewrite §2 from “one-off exception” to a bounded, named pattern: standalone informational pages live in frontend/public/ and are linked from the drawer, under stated conditions. One ADR edit, one HTML regeneration.
B — New ADR-091 A decision of its own for this page, citing ADR-085 §2 as the reason it exists, leaving ADR-085 untouched and still expiring with the calculator.
C — Build it as an application view instead The default route ADR-085 points at. No ADR exception needed at all, but it stops being an atomic file you can also hand to someone as an attachment or paste into WordPress.
Recommendation B — a new ADR-091. ADR-085 carries an expiry condition: when the proposed scoring is adopted, that page is deleted and the ADR is marked superseded. Folding a general pattern into a document scheduled for supersession would retire the rule along with the calculator. A separate decision keeps the two lifetimes apart, and it is the literal instruction in ADR-085 §2 — “its own decision”.

Q3 — Does this page also need to reach the association's WordPress site?

PROD is moving to the WordPress CMS, and ADR-090 publishes a PROD surface as a full-screen WordPress menu item. The drawer on Pages and the WordPress menu at weteraniszermierki.pl are two different menus. Adding the entry to the drawer does not put it in the association's own navigation.

Recommendation Start with the drawer only, and treat the WordPress menu item as a separate step once the page is live and you have seen it at its real address. Menu items cannot be verified over XML-RPC — they have to be built in wp-admin — so that step is manual either way and is better done against a page that already works.

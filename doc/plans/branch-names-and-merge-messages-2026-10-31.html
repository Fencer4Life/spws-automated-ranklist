03 · How

The rule and where it is enforced

  1. Naming. A worker branch is named after the change once its purpose is known, claude/<what-it-changes>, renamed with git branch -m before preflight if it started under another name.
  2. Describing. Before preflight, the worker writes the branch description: a title of up to 72 characters saying what changes, then a few sentences on why, what was wrong and what it does now.
  3. Preflight gate "branch, merge and release named (integrate)" in scripts/preflight.sh, beside the existing git diff --check (integrate): checks B2 on the current branch and prints the names the push will carry: the merge title, the CI run's title and the Release run's title. Skipped with --ci-only, since CI runs on main, not on a worker branch.
  4. Integration. scripts/integrate-agent-branch.sh refuses a branch without a valid description (the same check), and merges with the description as the message, followed by Branch: <name>, instead of --no-edit. The check lives in one script both use, so they cannot disagree.
  5. Release naming. .github/workflows/release.yml gets run-name: Release · ${{ github.event.workflow_run.display_title }}: the CI run's title, which is the merge title. A manual dispatch reads "Release · manual dispatch by <who>". The release-record commits that follow a release go through a described branch like any other change, so they are named the same way.

In python/tests/test_agent_worktree_operating_structure.py, run in throwaway git repositories as the existing integration tests are

  • A described branch integrates, and main's merge commit carries its title, explanation and Branch: line.
  • A branch without a description, with a title over 72 characters or starting "Merge", or with a one-sentence explanation, is refused, and nothing is merged.
  • A session-named, date-named or two-word branch is refused.
  • The preflight gate passes and fails on the same cases, and prints the merge, CI and Release titles.
  • release.yml names its run from workflow_run.display_title, with the manual-dispatch fallback (read from the workflow file, as the existing workflow tests do).

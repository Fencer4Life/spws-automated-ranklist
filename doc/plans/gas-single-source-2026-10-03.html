Twelve commands read or write the database through the Supabase Management API, with a token stored in the Apps Script project as SUPABASE_ACCESS_TOKEN. The commit of 19 June records that this token had gone stale and broke status and season. I cannot see the Apps Script project, so this one only you can check:

Send this in Telegram and tell me the reply

status PPW1-2026-2027

  • A status with counts (COMPLETED, 25 tournaments, 102 results): the token works.
  • Error: {"message":"Unauthorized"}: the token is stale. ! The e-mail intake

Every 5 minutes, unless paused, the bot uploads any unread e-mail with an XML or ZIP attachment to CERT storage and starts ingest.yml. That writes results straight into CERT under season 2025/26 and bypasses review. Nothing has used it since April; results now come from the organiser’s URL.

04 · How help stays true

A test that fails when help and commands drift apart

  • GAS.HELP.01: every command the bot handles has exactly one help entry, and every help entry is a command the bot handles.
  • GAS.HELP.02: every workflow the bot starts exists and declares every input the bot sends. This is the check that would have caught parity.
  • GAS.HELP.03: every help line for a command that touches data names CERT or PROD.
  • The new help opens with one line, “CERT = test database, PROD = public site”, and every entry gives the exact syntax with a real example, such as promote PPW1-2026-2027.
  • doc/handbook/operations/operator-runbooks.html gets the same command list as a table, so the handbook and the bot agree.

05 · Found while building

Issues, each fixed here

  • I31 — the security page was stale. doc/handbook/reference/security-posture.html said 33 visitor-callable functions; the allowlist held 37 before this change (FR-167 and FR-173 added four and the page was not updated). It now lists all 38, the four in a row of their own.
  • I32 — the hint widened the form. The first build let the hint's one long line set the section's width, so on desktop the section no longer fitted beside the other fields and the whole form reflowed. Caught by this sheet; the hint now takes no width of its own (contain: inline-size) and wraps inside the section, and a whole-pixel line height keeps the rows below on whole pixels.
  • The plan's save rule, corrected. The plan sent the switch only when the box changed. Unticking our registration without touching the box would then have left the switch on in the database, and switching registration back on later would have shown the places again. The form now compares „registration on and box ticked” with what is stored, and unticking registration also unticks the box (ELRANK.10).
  • A new event's form has no box. The plan said a new event starts with the box off; the create form has no „Rejestracja SPWS” section at all (registration is switched on later, in the edit form), so it has no box, reads nothing and sends nothing (ELRANK.10).
  • The migration, to the house pattern. The column is added last, as the one statement holding the table lock (as FR-172 and FR-173 do), so the SQL check finds nothing; the function is PL/pgSQL so it can be created before the column. Behaviour as planned (ELRANK.01–06, 22 assertions).
  • The mirror test proves it ran. A first version checked only that the switch was untouched, which would also pass if the mirror did nothing; each call now also renames the event and checks the new name arrived.

EVF history · data integrity · approved design

Consolidate predecessor-season EVF event fragments

Repair six source-verified physical events that were scattered across multiple PEW rows. Preserve the lowest established PEW number, merge only named fragments, clear demonstrably wrong rolling links, and leave historical season boundaries and every unrelated event untouched.

Design approved in conversationTDD requiredCERT → PROD

Decision

One physical event, one surviving event row

The repair uses the same transactional, result-preserving mechanism established by the 2025–2026 historical-fragment repair. For each reviewed cluster, the lowest existing event base survives. Its suffix becomes the union of the weapons actually held at that physical event. Donor tournaments and results move to the survivor; exact duplicate sporting slots collapse under evidence-first rules; only empty donor event rows are then deleted.

No chronological renumbering

The repair does not reflow any season. A survivor keeps its existing lowest number even when that number is not chronological. This is a historical identity repair, not a calendar reallocation.

No season-boundary correction

SPWS-2023-2024 retains its historical dates exactly as stored. The two 2022 rows and the season start date are explicitly outside this repair.

Atomic data flow

Fail before changing anything uncertain

advisory transaction lock
  → assert every named member exists, or all are already repaired
  → pin exact event / tournament / result / candidate / registration baselines
  → abort if any registration exists in a member event
  → choose each sporting-slot winner by reviewed source/full-field evidence
  → reconcile exact duplicate results and their match-candidate provenance
  → move retained tournaments and results to the survivor
  → rename survivor and child codes to the approved suffix
  → clear only the reviewed incorrect id_prior_event links
  → delete only now-childless named donors
  → recalculate only affected scored tournaments
  → assert conservation, uniqueness, donor absence and ranking invariance
  → commit atomically

Idempotency has two accepted entry states: the exact unrepaired baseline, or the exact fully repaired state. A partial or unfamiliar state raises an exception. This prevents a migration from guessing after CERT or PROD has drifted.

Evidence hierarchy

Sporting facts are not selected by row age

The original scoring provider and complete field are authoritative, consistent with ADR-028, ADR-039, ADR-043, and ADR-046. EVF calendar identity establishes the physical event; original scoring sites establish results, places, and field sizes. Equal-field disagreements, non-identical match-candidate provenance, code collisions, or unexpected result counts abort the transaction for operator review.

The repair never derives rolling continuity from a shared PEW number. A prior-event FK is nullable and may remain absent, as specified by the scoring and ranking handbook. Event ownership and calendar invariants follow the events and registration handbook.

TDD and acceptance

RED must prove the current fragmentation

  1. Add a dedicated pgTAP suite that names every survivor and donor and initially fails against the current seed.
  2. Assert canonical event codes, identities, weapon suffixes, tournament ownership, child-code prefixes, donor deletion, and zero registrations.
  3. Assert exact tournament, result, and match-candidate conservation. The LOCAL baseline contains 26 Budapest results, 11 Terni 2023 results, 10 Stockholm results, 9 Guildford results, 12 Terni 2025 results, and 89 Warsaw/Jabłonna results. LOCAL has zero cluster match candidates, while CERT has eight on Guildford; both are valid because result identities remain unchanged and the repair pins candidate count before and after each merge. The distinct PEW8f Guildford event and its 20 results stay untouched. Only a proven exact duplicate result or provenance row may reduce a count.
  4. Snapshot affected fencer/event points before repair and assert the same sporting points after consolidation, except where an official-source correction is separately and explicitly documented. This repair currently authorizes no point correction.
  5. Assert no duplicate (event, weapon, gender, age category) slot, no duplicate (tournament, fencer) result, no dangling match candidate, and no remaining reference to a deleted donor.
  6. Run the migration twice in the test database and prove the second pass is a no-op.

The repository-wide database baseline, traceability totals, specification, ADR source documents, generated ADR HTML, and current handbook pages change together under the traceability standard and documentation coherence gate.

Deployment

One reviewed migration, promoted consistently

The implementation is a forward-only Supabase migration plus pgTAP evidence and coherent documentation amendments. LOCAL proves RED/GREEN and repeatability. The validated branch is integrated through the clean integration checkout. Release applies the same committed migration to CERT, verifies the post-state, then applies it to PROD after the protected-environment approval and verifies the same post-state.

Production hard stop

If CERT differs from the pinned baseline, PROD is not attempted. If PROD differs from the pinned baseline, the transaction aborts without partial changes. No manual DELETE and no environment-specific mapping are allowed.

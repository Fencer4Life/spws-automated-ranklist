What the new engine does to a real PPW1

Last season's 23 PPW1 brackets, rescored under SPWS_FIELD_SCALED_V1_2026_2027. Every winner's score falls, by 14% in the largest bracket and 68% in a walkover. The event total drops 32.9%. This is the curve working as designed — but the size of it is worth seeing before the real results land.

LOCAL fixture only 23 brackets · 85 placements 8 walkovers real results ≈ 29 Sep 2026

Why PPW1 is the sharpest probe

Every one of its fields is below the crossover

The two engines differ only below N = 32, where 10 × log₂(32) = 50 makes the field-scaled base reach mpValue and the curves meet. PPW1's fields run from 1 to 11. Not one bracket reaches the crossover, so every single one moves — which makes this event a worst case rather than a typical one.

An EVF event with a field of 60 would show no change at all. The reduction below is specific to small domestic fields, which is exactly the population the curve was designed to re-price.

Across all 85 placements, not just the winners: 3298.88 → 2214.68, a fall of 32.9%.

→ The loss is a flat 40 points wherever the base is capped by the field

At N = 1 and N = 2 the base falls from 50 to 10, and the other two terms are untouched, so the whole difference is exactly −40.00. As the field grows the gap narrows — −15.41 at N = 11 — and closes completely at N = 32. The DE bonus and the podium bonus are identical under both engines; only the base changed.

What this does NOT show

Rank order is untouched here, and that is not the whole story

Within a single event the ranking order cannot change. Both engines are strictly decreasing in place for a fixed field, so every fencer in a bracket moves down together. I checked, and the order is identical.

! The order effect needs a second event, and it will come

The engine changes relative standing only when a fencer's counted results span fields of different sizes. A fencer whose best-4 came from small brackets loses more than one who fought large ones, so the two can swap. With PPW1 alone in the season there is nothing to swap against. Expect this to appear once the season holds two or more events, and do not read the unchanged order below as evidence it will not.

× Do not compare this season's totals against last season's ranklist

It is tempting and it is wrong. The 2025/2026 ranking sums a whole season's best-4; 2026/2027 currently holds one event. A fencer's number will look far smaller for that reason alone, which has nothing to do with the engine. Only the per-bracket comparison above isolates the engine.

The real PPW1 2026/2027 results arrive on CERT in around ten days and will use these same canonical tournament codes. Run --remove, or reset LOCAL, before ingesting them there, so a test copy can never be mistaken for the real thing. Two things the fixture exposed

Neither is a scoring defect, both are worth knowing

1 A PLANNED event contributes nothing, however well scored

vw_eligible_event excludes CREATED, PLANNED, SCHEDULED, CHANGED and CANCELLED. My first run scored all 85 placements correctly and the ranklist was still empty, because the calendar row was still PLANNED. Real ingestion advances the status; the fixture now does the same, one step at a time because the transition trigger refuses a jump.

2 Copying results across a season boundary needs the source bracket label

Without enum_source_age_category, trg_assert_result_vcat re-derives each fencer's category from birth year against the new season's end year, and anyone who aged up between the two seasons is rejected. That is the cross-season conflict ADR-056's "bracket-label wins" revision exists to prevent, and it is the same reason real ingestion writes that column.

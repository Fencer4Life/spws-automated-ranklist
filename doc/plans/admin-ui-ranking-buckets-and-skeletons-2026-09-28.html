! Why PPS and MPS can't be picked in the editor

Both bucket pickers read two hard-coded lists in ScoringConfigEditor.svelte:519: ['PPW','MPW'] and ['PEW','MEW','MSW','PSW']. The lists date from 27 March 2026 (70e4df53). PPS and MPS became types on 19 September (bb5596b7), which added their multiplier cards and engine wiring but not the picker lists.

The same code shows every listed type in both pools. That's how PROD ended up with a PPW bucket in the international pool.

Why nothing is counted twice

Each type sits in exactly one bucket. fn_ranking_full ranks candidates within each bucket separately and takes a result into a bucket only when its type is listed there, so a result can only count in its own type's bucket.

fn_ranking_ppw reads the domestic pool alone, and fn_ranking_full adds the international pool as the EVF+ column. Carried PPS and MPS results never count (SS26.RANK.12).

New: PPS and MPS results will count in the 2026/27 full ranking. No ranklist has shown them before.

Why not through the editor. The editor can't select PPS or MPS until Part 2 ships. The rules go in through fn_import_scoring_config, the same call the editor's Save makes (api.ts:344), so the ADR-097 lock applies exactly as it would to a UI save.

Part 2 · A · the gap behind PROD's ignored buckets

Refuse invalid buckets in the editor and on the server

RuleRefused exampleWhat it prevents

On the server

  • A new internal function, fn_validate_ranking_rules_write(jsonb), with no grant. It raises a message that names the bucket and the rule it breaks.
  • fn_import_scoring_config calls it only when the incoming rules differ from the stored rules.
  • Rules in the newer three-section shape (schema_version: 2) are already refused by fn_ranking_rules_canonical for the same faults. The engine's reading of stored rules doesn't change.

! Why "only when the rules change"

The 2024/25 and 2025/26 rules repeat the domestic buckets in the international pool; that's the older format, and the engine drops the copies. Every Admin save re-sends the whole configuration, for example when the +EVF toggle changes, so an unconditional check would make those seasons unsavable.

With the check scoped to changes, they save as before and their rankings don't move. A new season inherits the previous season's rules (FR-21), so the wizard passes as well.

In the editor

The editor is ScoringConfigEditor.svelte, used by the season form and the season wizard. The checks live in a new pure module, frontend/src/lib/ranking-rules.ts, which mirrors the server rules and is tested on its own.

  • Each pool's picker offers only its own types. PPS and MPS are added to the international picker, with the red PZSz colour.
  • A type already used in another bucket shows as disabled. "Best" can't go below 1, and "best" and "all" are mutually exclusive.
  • A loaded bucket that breaks a rule shows a warning under it, for example "Silnik pomija ten kubełek" or "Ten typ jest już w innym kubełku".
  • Saving is refused, with a Polish message, only when the rules changed and are invalid. That matches the server.

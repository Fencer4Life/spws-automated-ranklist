1 · What is being built

A public page on weteraniszermierki.pl — same treatment as /znajdz-zawody/, not a menu item — from which the organizer of PPW1-2026-2027 downloads FIE-XML files and loads them straight into Fencing Time: a mix-all pool per weapon seeded in the ADR-080 §2 snake order, one DE file per gender × age category actually present, and a roster file per weapon so a fencer who turns up unannounced is ticked in rather than typed. Plus a PL and EN instruction manual. Before any of that, a registration-identity block that stops the same person entering the organizer's software twice. PPW1 is on 26 September; registration closes 20 September.

6 · Traps

  1. Do not widen the marker regexes. The decision is the age digit only; gender travels as the FIE Sexe attribute. Unifying the four regexes into vcat_marker.py is a pure refactor — if a test changes behaviour, the refactor is wrong.
  2. Do not bypass trg_fencer_change_enqueue. A birth-year write must be a plain UPDATE. Anything that disables triggers leaves the ranking inconsistent with no error — trg_assert_result_vcat does not fire on tbl_fencer.
  3. Do not loosen fn_match_registration_fencer. Its exact-tuple strictness is deliberate: it can never merge two people. The new candidate function is additive and only runs when the fast path misses. 36 of 43 registrations must keep taking the existing path untouched — that is the regression test that matters most.
  4. Never let a name-based rule act on more than one row. MŁYNEK Janusz is the fixture. Silent writes to the wrong one of two identical names are unrecoverable.
  5. fn_confirm_registration_identity must recompute the candidate set server-side and refuse a p_id_fencer outside it. Without that check, a caller could name any fencer and rewrite their birth year.
  6. Never run a bare supabase db reset — use ./scripts/reset-dev.sh. LOCAL data is not PROD data: LOCAL carries triplicated result-less rows that PROD does not.
  7. Do not write test data to PROD. If a write is unavoidable, prove the delete path first — see the cloud-db-ops skill.

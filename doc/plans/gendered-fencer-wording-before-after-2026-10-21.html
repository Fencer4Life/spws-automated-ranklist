The same sequence is now an automated test, GW.APP.02 in AppShell.test.ts, so a later change cannot quietly break it.

5 · Tests and checks

RED first, then GREEN

  • New tests: GW.RT.01–02 (table header), GW.DD.01 (tooltip), GW.APP.01–02 (dropdown → header, back and forth). All five were run and seen failing on the old code before any source change.
  • One test fix along the way: the first version of GW.APP fired before the seasons loaded. At that moment the dropdowns sit at other positions, so it changed the category instead of the gender. The test now waits for the seasons and finds each dropdown by its options. I then removed the gender link from App.svelte to confirm the test fails without it, and put the link back.
  • Whole suite: 70 files, 1,243 tests pass. svelte-check: 0 errors and 21 warnings, the same as before the change, none in the changed files.

6 · Release, after your approval

The release steps

  1. One sentence in the handbook (Product Surfaces → Ranklist) on the rule, then reindex the documentation search and refresh the code graph.
  2. scripts/preflight.sh must exit 0, then commit on claude/gender-specific-verbiage.
  3. Push to main from the integration checkout. This puts the bundle on PROD's WordPress pages with no approval step.
  4. Check CERT and PROD in the browser: the women's list says „Zawodniczka”, the men's list „Zawodnik”.

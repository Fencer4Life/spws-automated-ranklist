2 · Meaning

What "closed" means here

  • The closed states are COMPLETED and CANCELLED (Event status lifecycle). All six events took place, so the right one is COMPLETED. For DMEW and the PZSz cup, that means COMPLETED with no tournaments.
  • On the calendar card, a COMPLETED event shows the "Completed" chip. Results links appear only when the event has result URLs (EventCard.svelte, the hasResults && urls.length > 0 check). An event with no tournaments therefore shows the chip and no empty links.
  • The database refuses PLANNED → COMPLETED in one step (fn_validate_event_transition). A PLANNED event steps through IN_PROGRESS, the way promote does, inside one transaction. An IN_PROGRESS event closes through fn_complete_event('<exact code>'), the function behind the Telegram complete command. It accepts an exact code from any season and moves only IN_PROGRESS → COMPLETED.
  • It can be undone. The validator allows COMPLETED → IN_PROGRESS and COMPLETED → PLANNED. If results turn up later, the event can be reopened and ingested.

4a · Ingestion first

What the two active-season events have to ingest

Poznań, PPS1s-2026-2027: none of our fencers took part

The PZSz event page (id 4588) lists two individual tournaments, both dated 4 October 2026: men’s sabre (turniej 10628, 53 starters) and women’s sabre (10629, 46 starters). Each start list carries birth dates. V0 is age 30–39 in the season’s end year, 2027, so only three starters are old enough for any veteran category: Kaczkowski Krzysztof (1997, men), Drygała Gabriela (1995) and Szumilas Nikola (1994, women). Everyone else is born in 2000 or later.

None of the three is in CERT’s fencer table, under any spelling with Polish letters folded, nor in any fencer’s aliases. Fencer ids are identical on CERT and PROD (ADR-108). PZSz ingestion links only an exact name or an approved alias and never creates a fencer (ADR-100). So an ingestion would store no result for this event.

A second limit: our flow reads FencingTimeLive. PZSz publishes this event’s results on its own site (the tabs Grupy, Ranking Grupowy, Tabela and Klasyfikacja końcowa). I found no FTL listing for it, and ADR-100 records that no real PZSz bracket had been verified when the flow was built.

Budapest, PEW1f-2026-2027: nothing published

EVF’s event page links only the invitation letter, no results. EVF files it under “Foil, Outdoor Fencing”, not “EVF Circuit”. EVF’s results API lists no 2026/27 event at all. There is nothing to ingest yet.

6 · Deferred

Team results: another day

Your question was whether team results should be ingested into a separate table. It is not decided and not part of this page. My first thought, for when we return to it: yes, a separate table, if they are stored at all. A team result belongs to a team (a country and its members), not to one fencer. tbl_result feeds every ranking through vw_eligible_event, so keeping team results apart keeps them out of the rankings by construction. The questions for that day are what a page would show, and whether a biennial event justifies the work.

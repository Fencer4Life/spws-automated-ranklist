02 · The protocol

What scripts/session_start.py does, in order

A SessionStart hook in .claude/settings.json runs it on startup, /clear and resume. A SessionEnd hook runs a small companion that records the session as ended. The hook never blocks a session: it always exits 0 and reports its failures as text.

  1. Isolate. A session that starts or /clears in a shared checkout (the primary checkout or the integration checkout) gets a new worktree on a new branch from origin/main. A session that resumes, or starts inside a worker worktree, stays where it is. See §03.
  2. Baseline. git fetch origin, bounded to 20 s so an offline start does not hang. Report the branch, commits ahead of and behind origin/main, and uncommitted files. A worker worktree that has no commits of its own, is clean and is behind is fast-forwarded, which is safe. Anything else that is behind gets a loud STALE line.
  3. Clean up. Remove Claude's own finished worktrees by the rules in §04. List the ones that need your decision.
  4. Graph. A full-code refresh in the working checkout, run with the protocol's own copy of graphify_refresh.py. A new worktree is first seeded with only the four portable graph files (graph.json, manifest.json, .graphify_labels.json, GRAPH_REPORT.md), never .graphify_root or .graphify_python, which the handbook forbids copying. Nodes of files the tree lacks are pruned, and any file still on disk that lost nodes is named in the report.
  5. RAG. tools/docs-search/ingest.py runs only if the checkout is not behind origin/main. A lock allows one ingest at a time. See §06.
  6. Report. One line for you, such as SPWS session: claude/session-20261003-0912 · graph 12,845 nodes · RAG 4,069 chunks · 1 worktree removed. A full block for Claude. Its first instruction is "call EnterWorktree(path) first" when a worktree was made, followed by the research rule: docs through the RAG, code through the graph.

03 · Parallel sessions

A new branch is not enough. Each session needs its own worktree.

Two sessions in one folder share one set of files. If one session switches branch, the other session's files change under it. Parallel work needs one folder per session. Your handbook already says so: "Run Claude and Codex in the same folder" is listed under What nobody should do (doc/handbook/operations/claude-codex-collaboration.html).

Reuse what exists: scripts/start-agent-worktree.sh

The hook calls the existing script from the registered integration checkout (/Users/aleks/coding/SPWSranklist-integration):

bash scripts/start-agent-worktree.sh claude session-20261003-0912
  → branch  claude/session-20261003-0912      (from the latest origin/main)
  → folder  /Users/aleks/coding/SPWSranklist-claude-session-20261003-0912

The script already refuses duplicates, a dirty integration checkout, or an integration checkout that is not on main/integration/main. If it refuses, the session stays where it started and the report says why. When the task becomes clear, the session renames its branch to say what it is: git branch -m claude/<task>.

  • Moving the session. A hook cannot change a session's folder. The report tells Claude to call EnterWorktree with the new path as its first action. That tool accepts any worktree listed by git worktree list. CLAUDE.md gains one line saying so, because the tool may only be used when project instructions call for it.
  • Ready to run. The new worktree gets .venv as a symlink to the primary checkout's environment, which is already the precedent in SPWSranklist-claude-season-scoring-contracts. It also gets frontend/node_modules symlinked the same way. Both names go into .git/info/exclude without a trailing slash, so the symlinks never show up as untracked files and never block cleanup.
  • When it does not fire. On resume the session keeps its folder. Sessions the desktop app already placed in a worktree, and sessions opened in an existing worker folder, stay where they are.

04 · Cleanup

Remove only what can lose nothing. Report the rest.

A worktree is removed automatically only when all five conditions hold:

  1. It is Claude's. Its branch is claude/*. Codex worktrees, the integration checkout, the primary checkout and the current session's own worktree are never touched.
  2. All its commits are on main. git merge-base --is-ancestor <branch> origin/main, which also covers a session that never committed. A squash-merged branch fails this test, so it is kept and listed. The cost is only a reminder.
  3. It is clean. git status --porcelain shows nothing, untracked files included. This is what protects untracked plans, such as the joined-scoring spec in fervent-antonelli-be346d.
  4. No session is using it. Either the SessionEnd hook recorded its session as ended, or nothing has touched it for 30 days (no index or HEAD activity). The 30-day fallback covers worktrees made before this protocol existed.
  5. Git agrees. Removal is git worktree remove <path> without --force. Git itself refuses a dirty tree, which is a second lock on condition 3.

Then the local branch is deleted. Condition 2 has already proven its commits are on main. Remote claude/* branches are left alone (decision D4). git worktree prune drops registry entries whose folder is already gone.

! Never, under any condition

No --force, no git clean, no reset and no stash on another worktree. Nothing with uncommitted or untracked files is removed, and nothing that holds a commit missing from main. These are the handbook's own "can destroy unfamiliar work" rules.

06 · The RAG

One shared index, so only an up-to-date checkout rebuilds it

Every checkout feeds the same Meilisearch index, and ingest.py is authoritative in both directions: whatever the run does not see, it deletes. An ingest from a checkout that is behind origin/main would remove newer ADRs and handbook pages for every session. So the hook rebuilds only when the checkout is not behind main. Otherwise it leaves the index alone and says so.

Known limit: untracked documents live in one checkout only

A plan that exists only as an untracked file in one worktree is in the index until another checkout rebuilds it. Today that is the joined-scoring spec in fervent-antonelli-be346d. The protocol does not fix this. Committing plans does. Teaching ingest.py to also collect untracked doc/ files from every registered worktree is possible, but it is a separate change. Tell me if you want it.

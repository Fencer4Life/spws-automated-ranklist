Why

  • D1 A. Dropping the columns puts at risk exactly what you asked me to protect, for no gain.
    • vw_calendar selects both columns, and the registration form reads that view. Registrations are the data the seed files are built from. Removing a column from a view means dropping and recreating it, together with its grants.
    • The seed dump that every LOCAL reset and every CI run loads (supabase/seed_prod_latest.sql → seed_prod_2026-10-17.sql, wired in supabase/config.toml:74) names ts_ftl_sent in all 104 event rows. A dropped column breaks the bootstrap until the dump is regenerated.
    • Both columns are empty on every event on CERT and PROD (checked today), so keeping them costs nothing. They can be dropped later, together with a seed regeneration.
  • D2 A. The field exists only to give the send a recipient, and nobody has ever filled it: 0 of 104 events on CERT and on PROD. fn_update_event keeps its p_txt_organizer_email parameter (default NULL = leave unchanged), so the form simply stops sending it. No SQL signature changes.
  • D3 A. The handbook already states that nothing in the system sends e-mail. Today the only code that does is the sender being removed: smtplib and email.message appear nowhere else in python/, scripts/, frontend/src, the edge functions or the workflows. The guard turns that statement into a test.
  • D4 A. The documentation standard archives superseded pages and keeps the files and their history. Only doc/handbook/documentation-map.html links to this page.
  • D5 A. ADR-080's 2026-09-25 amendment already took the decision (withdrawn, never commissioned). This amendment finishes it: the code is gone, not "retained unused". A new ADR would split one decision across two records.
  • D6 A. Every suppression covers only the statements the checker cannot read, and says why. A real defect next to them is still caught (canary in § 13). An unused suppression is itself a warning, so preflight fails once one goes stale. B leaves whole files unchecked. C changes working tests to suit a tool.
  • D7, done here. My recommendation was a separate release; you told me to fix it here, so I did. The protected-path proof is unaffected: the fix touches one EVF function and one EVF test file, neither on the protected list (§ 5).

§ 11 · ADR draft — Status: Proposed

ADR-080 amendment (2026-10-24): the e-mail delivery is removed

Context. The 2026-09-25 amendment withdrew §5's e-mail delivery as never commissioned, but kept its code "retained, unused". That left a workflow running a skipped job every day, a send button in the admin form, and a dispatch route to it. The association holds no registered sending identity, and the decision is final: seed files will never be e-mailed.

Decision. The delivery is removed from the tree: ftl-seed.yml, python/pipeline/ftl_feed_seed_send.py, DbConnector.mark_ftl_sent and list_ftl_delivery_candidates, fn_mark_ftl_sent, the event form's send button, "last sent" field and organizer e-mail input, and the dispatch-workflow allowlist entry. Tests NOMAIL.01–07 fail if any of these, or any outbound e-mail code, returns.

Unchanged and in service. Seed generation (§1–§4 and amendments (b)–(h)): ftl_seed_export.py, ftl_seed_export_db.py, vcat_marker.py, ftlSeedExport.ts (byte for byte to the Python), zip.ts, exportArchive.ts. The organizer download page reached by the capability link (amendment (h), ADR-093, ADR-095) is the only handoff.

Retired, not dropped. tbl_event.ts_ftl_sent and tbl_event.txt_organizer_email remain as columns, empty on every event on CERT and PROD (checked 2026-10-24). No code reads or writes them. They stay because the seed dump every LOCAL and CI bootstrap loads names them, and because vw_calendar, which the registration form reads, selects them. Dropping them belongs with a future seed regeneration.

Alternatives. Keeping the code unused, the 2026-09-25 state, was rejected: it kept dead triggers live. Dropping the columns now was rejected: it would touch the registration view and the bootstrap for no functional gain.

Consequences. Any organizer handoff by e-mail needs a new ADR, and the NOMAIL tests will name it. ADR-086's note that ts_ftl_sent is "stamped per environment by ftl_feed_seed_send.py" and ADR-087's listing of ftl-seed.yml::deadline-sweep in the prod-write group each get a one-line pointer to this amendment.

  • Fixed here. supabase/migrations/20261024000002_fix_evf_create_ambiguous_id_event.sql is a CREATE OR REPLACE identical to the current body except one line: WHERE tbl_event.id_event = v_id_evt AND tbl_event.id_evf_event IS NULL. Grants unchanged (authenticated only).

Decided

Five decisions: all A, approved by you in chat on 17 October

Q1 · The daily EVF results sync

Today it writes EVF results into CERT outside any run record. Promote then has no CERT run to replay, and the next sync can overwrite what ingest wrote.

A (recommended): the sync keeps the calendar and stops writing results. When EVF has results for an event of ours, it sends Telegram “results available: ingest <code>”.

B: keep it writing CERT as today.

Q2 · Per-tournament scrape to PROD

A (recommended): scrape-tournament.yml refuses target=prod, as ingest … prod already does, so PROD gets results only through promote.

B: keep it.

Q3 · Where an EVF event’s results come from

ADR-105 §1.5: the organiser’s results first (FTL, Engarde, 4fence, Ophardt, d’Artagnan), then EVF’s own results only when nothing else exists.

A (recommended): ingest reads every result URL of the event (url_event … url_event_5). When none is set, it reads the EVF results.

B: refuse until a URL is set.

Q4 · CERT starts from PROD’s master data

Promote refuses when PROD’s inputs (roster, aliases, season settings) differ from what the CERT run started from (ADR-108 §5). Today the refresh from PROD is a manual runbook step, and Telegram ingest does not run it.

A (recommended): ingest runs the refresh first. A refresh that renumbers nobody and leaves nobody unpaired is applied automatically. Anything else stops the ingest with the refresh report, as ADR-108 §2 requires.

B: keep the refresh manual.

Q5 · The Phase 5 runner

A (recommended): keep it for LOCAL work and for repairing a past-season event on your explicit request. New events of any organizer use ingest and promote only.

B: remove it.

Design

What gets built

  1. DRIVER _ingest_international_event_rounds in ingest_cli.py, chosen in _ingest_event_rounds by _is_international_intake, in the place PZSz’s driver is chosen. Ingest on CERT and promote’s plan on PROD both call _ingest_event_rounds, so both run it, as ADR-111 §6 requires. It reads every source URL through Fetcher.fetch_event_url_with_skips (review_cli.py:277), which already reads FTL schedules, Engarde, 4fence, Ophardt and d’Artagnan, plus the EVF fallback under Q3. It skips team brackets and FTL listings that are not finished (lifecycle.split_final). It refuses a bracket without one V-category, and two sources for one bracket.
  2. FLOW A new Flow.INGEST_INTERNATIONAL in engine/flows.py and engine/rulebook.py: ParseSource, ValidateIR, ResolveEvent, ResolveFencers, ValidateCounts, AssignFinalVcat and Commit. It drops the domestic split, combined-pool and joint-pool steps, which recount and renumber. organizer_hint is EVF or FIE.
  3. REFUSALS Remove ingest_cli.py:630 and promotion/plan.py:322. Extend the run record and promote’s source check to listings that are not on FTL: hash by source URL, record all five URL slots, and fill a blank slot on PROD from CERT (ADR-086’s fill-blank tier, today url_event only).
  4. LIFECYCLE A listing from a source with no “Finished” flag counts as final once its results are published. The daily close (event-close.yml) covers every organizer of the active season, PZSz included.
  5. REPORT Port Phase 5’s international section (phase5_runner.py:1851) into the staging report ingest sends: per bracket the source N, the stored rows, foreign rows, PENDING with candidates, and the FIE flag for more than 4 rows of one federation.
  6. WRITERS Q1, Q2, Q4 and Q5 as decided. The Telegram ingest and promote texts and /help name every organizer.
  7. DOCS A new ADR-113, “Ingest and promote carry every organizer”. It amends ADR-108 §9 and its 2026-10-06 amendment, ADR-105 §5.6 (the international flow now exists), ADR-111 §6 (EVF done) and ADR-106 (the paths). The spec registry, the RTM, and the handbook’s ingestion page, runbooks and workflow catalog change in present tense.

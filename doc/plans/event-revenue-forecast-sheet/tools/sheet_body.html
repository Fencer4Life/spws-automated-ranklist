05 · The event form

One block after the entry-list link

„Link do prognozy przychodu (dla organizatora)” comes in three states. Each pair below is mapped row by row against main: rows above the block are identical in place, and every row below is identical, shifted by exactly the block's height. On desktop, after a whole-pixel shift, a handful of pixels inside native controls far from the block (the date input's calendar icon, the select's arrow) differ by at most 2/255. That is how the software rasteriser anti-aliases a native widget at another height; on a phone the same pairs are exact. The first build also left the block a fraction of a pixel tall, because of native buttons at 13.333 px. Its three controls are now 22 px. The block takes no width of its own (I32): the input may shrink, the buttons wrap, and the hint uses contain: inline-size with whole-pixel line heights.

07 · Found while building

Issues, each fixed here, and where the build differs from the plan

  • I33: the allowlist sync check read a fixed window. scripts/check-anon-allowlist-sync.sh took the 140 lines above label 52.7. With this justification added, the list starts 150 lines up, so the check misread it. It now reads from the list's own ARRAY[, at any length.
  • I34 — gone with the roster. The roster's „Wpłata potwierdzona” header did not fit 18 mm; the roster tab is removed (your change), so the issue went with it.
  • I35: the entries total printed as „###”. The plan fixes the column widths to fill A4, and a bold four-figure sum with its currency did not fit 22 mm. Every money cell now shrinks to fit (REVFC.24).
  • I36: no test covered register.html's view switch. The plan said to extend the existing one, but there was none. frontend/tests/registerHtml.test.ts now runs the page's own script for every view (REVFC.30).
  • I37: two test files differing only in case. The plan names both revenueReport.test.ts (the module) and RevenueReport.test.ts (the page). On macOS, writing the second overwrote the first. The page's tests are RevenueReportPage.test.ts, and the RTM says so.
  • I38: t() filled only the first occurrence of a placeholder. The missing-tier note names its number twice and came out as „przyjęto {n} ×”. tIn now fills every occurrence (locale-interpolation.test.ts, seen failing first).
  • I39: the Sidebar tests logged jsdom navigation notices. Three „Not implemented: navigation” lines appeared on every run. The WP.NAV tests now read whether the component cancelled the link, then hold the navigation back. Their assertions are unchanged.
  • I42 — the page cut long totals in print. In the file's millimetre widths „11 910,00 EUR” did not fit 22 or 24 mm and was cut off („11 910,00 EUI”). Every money cell now carries its column's width and its text's length, and print shrinks only a text that would not fit (REVFC.32), as the file's cells do (I35).
  • I40: the revenue figure overflowed on a phone. „3100,00 PLN” at 24 px ran past its third of the card. On a phone it is now 17 px and may wrap before the currency (section 03).
  • I41: a worker worktree has no .venv and no .env. Preflight's Python gates found no python. The cloud checks then read the environment's stale token, and the RAG re-index at session start failed for the same reason. All are untracked files of the primary checkout. They were linked into this worktree (gitignored, nothing committed), and preflight then passed. The cause, the session-start hook not linking them, is still open: proposed as a follow-up.
  • Your change, as built. The file's roster tab (REVFC.31) is removed and its test retired; the entries tab is unchanged, now with its own print range. The page keeps its entries below the summary and gains the file's total row. While the report shows, the document carries the paper and footer (a rule inside the element cannot), and the rows print at the file's 6 mm, so the page counts match.
  • The division in the weapon × gender formulas is guarded. The plan's …*I/H divides by zero for the empty row of an event without entries: LibreOffice gave an error, not 0. The divisor is now (H+(H=0)), which equals H for every real entry (REVFC.23, and no error cell in the LibreOffice proof). For you to confirm.
  • The report page paints its own background. register.html's body is dark navy for the other views. For view=revenue it is now the report's light grey, without the dark frame (Q1 = A; REVFC.30 checks both).
  • Wording lives in one place. The .ods reads the same rev_* keys in pl.json/en.json as the page, so their words cannot drift apart.
  • „1 360,00” versus „1360,00”. On the page, Polish money follows the browser's rule, which groups from five digits („7950,00”, „12 345,00”). LibreOffice groups from four. The numbers are equal, and only the spacing differs.

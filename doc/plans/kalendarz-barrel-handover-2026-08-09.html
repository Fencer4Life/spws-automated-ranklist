Why the geometry lives in the pure module, not the component

jsdom has no layout engine. Every clientWidth there is 0, so the overlap maths — step, margins, z-index — can never be asserted through a mounted component. It would silently test nothing.

So it lives in layoutRow() and is asserted directly (CQ.59–69), and CalendarBarrel treats a measured width of 0 as "not yet measured" and renders a flat row with no inline geometry. That is also correct for first paint. The barrel's own test file states this explicitly at the top — do not "fix" it by trying to assert widths in jsdom.

Locale keys added

Every fee, status and link key already existed — no new strings were needed for those. What was missing:

  • cal_month_1…12 and cal_month_short_1…12 — the calendar needs genitive months (18 kwietnia). Verified that the existing month_1 is Styczeń, nominative, so borrowing it would have read wrongly.
  • tournaments_one / _few / _many — the three-form Polish plural, replacing the flat tournaments_count.
  • copy_address, copied, event_results_day, event_awaiting_message, event_cancelled_message, calendar_empty_quarter, calendar_next_up.

03Five corrections made this session — do not re-introduce

0. The focused row must scroll — overflow-x: hidden stranded panels

Found by re-checking Phase 3 against the mock rather than trusting this handover's own DONE. The mock carries two overflow rules — .rw{overflow-x:auto} and .up .rw,.dn .rw{overflow-x:hidden} — and the component had collapsed them into hidden for every row.

That matters because layoutRow stops absorbing overflow at PANEL_STEP_FLOOR (13px). Past it the row is genuinely wider than the viewport: at 320px the content width (n−1)×13 + W_last exceeds 320 from n = 22 (at 360px, n = 26). A panel is reachable only by tapping it — rotation moves between rows, never within one — so clipping stranded the trailing panels with no way back. ADR-084's own acceptance criteria already presume a scroll container (not clipped by the row's scroll container), so this was a slip against the spec, not a design choice.

Worse, it needed no user action: selectDefault() opens on the next-upcoming event, which in a long quarter can sit past the clip edge — an invisible selection with the caret computed off-screen.

Fixed: the two mock rules restored; contentWidth now returned by layoutRow (CQ.70) instead of being recomputed in the component; caret math moved into the pure module as caretOffset() with the mock's viewport clamp (CQ.71, CQ.72, CQ.72b). Browser-measured at 320px with 22 panels: content 351px, maxScrollLeft 31px, trailing panel fully reachable after scroll, receded row still hidden.

1. "Carried" is not a calendar state — a false blocker I raised

I escalated ADR-018's carried state as a decision blocking the barrel's visual spec. It is not. positionSlots at CalendarView.svelte:268 computes exactly one boolean, completed; the template renders class:completed/class:planned; the CSS covers those two only. The word carried and the ↩ glyph appear nowhere in that file.

ADR-018's three-state calendar description documents a strip that was never built. Carry-over is a ranking concept, surfaced only in DrilldownModal.svelte:49-104 via bool_has_carryover. A calendar has no carried state to lose. Nothing is blocked; the fill-and-ring scheme is complete as designed.

2. Flag collisions I shipped and then fixed

Rendered as plain bands, Croatia is red/white/blue exactly like the Netherlands, and Slovakia and Slovenia are white/blue/red exactly like Russia. Their emblem is the only difference, so band-only rendering was actively wrong. Greece was also wrong — 5 bands instead of 9 stripes with a canton — and Laos was drawn as a plain blue field because its disc sits over stripes the primitive cannot express.

Now: 7 hand-drawn SVG flags (GB, GR, HR, SK, SI, RS, PT), Laos removed, and CF.20 pins that the three former colliders differ from each other and from their band-only twins.

3. Images are not banned — document-relative src is the problem

I over-claimed that a flag image was impossible under ADR-007's CSP. The real constraint is narrower and worth carrying: SPWS-logo.png is referenced as src="SPWS-logo.png", document-relative, so inside a custom element on a third-party page it resolves against the host's URL and 404s. That is a latent bug in the logo, not a pattern to copy. Inline SVG has neither problem — no request for CSP to block, no URL to resolve wrongly — and is authored rather than downloaded, so provenance is not in question.

4. svelte-check caught two type errors the tests did not

TypeScript will not subtract both literals from a union member whose own discriminant is a union (kind: 'h' | 'v'), so a fall-through branch was unnarrowed while all tests were green. Fixed by narrowing positively. Run npm run check, not just vitest — it is the gate that caught this.

04Deliberate choices worth not relitigating

  • Flag scope is "only what renders correctly." Emblem-bearing flags that would collide with another country are omitted, not approximated — an unlisted code renders nothing and the card shows the place without a chip. Italy/Mexico, Ireland/Côte d'Ivoire, Romania/Chad and Monaco/Indonesia are the live examples; the emblem-bearing member of each pair is the one dropped.
  • Identity and rendering are separate. countryCode() resolves ~120 names, more than there are drawable flags. GB resolved before it was drawable, and CQ.46 pins that separation.
  • The reduced-emblem tier is labelled as such. Croatia gets a two-square checker, not a faithful chequy. At 19×13 a real coat of arms is sub-pixel; the mark's job is to disambiguate.
  • mpw is kept distinct in both the module and the barrel's classes, even though it currently paints like ppw, so the past-season-anchor item stays a styling choice rather than becoming a prerequisite.
  • findNextUpcoming skips cancelled events. Ringing a cancelled competition as the thing to look forward to would be wrong. Not pinned by a test — worth adding one.
  • allowsFeeTier permits a tier when the weapon count is unknown. Suppressing real pricing on missing metadata is the worse failure (CQ.51).
  • t1/t2 text tiers are now live. They are dead CSS in the mock — defined, never applied. Here they are driven off the overlap step, so a code still fits its panel at tight steps. This is an addition beyond the mock's observed behaviour.

07Still open

1. What the card opens on

Unresolved. resolveAnchorQuarter() currently implements the mock's next-upcoming default, which was demonstrated but never chosen. The time-sensitive policy — the result for seven days after an event ends, then the next upcoming — is not applied.

Recommendation unchanged: time-sensitive. The seven-day window already exists for cancelled-event notices. It is a self-contained change in one function.

2. Past-season anchor

Finished seasons have no next-upcoming, so the drum loses its focal point. The mpw and int buckets are preserved specifically so championships can be marked without new machinery.

Recommendation: mark championships distinctly. Nothing is blocked on it.

3. How far to take the flag set

Asked and left open. Roughly 140 countries are drawable exactly with geometric primitives; the remaining ~55 need faithful emblems that are not hand-authorable at quality. Every country in the observed CERT data is already covered.

Recommendation: leave it. Expand against a list of countries that actually appear, not speculatively — a 200-country file was written and deleted once already this session.

4. Public embed — verify, do not fix

ce/CalendarElement.svelte derives demo ? MOCK_CALENDAR_EVENTS : [], meaning the non-demo embed renders empty. Confirm how the production spws-calendar element is actually fed before changing anything; if it is genuinely unwired, that is a separate report.

5. A default selection can still open off-screen

Residual from correction 0. The trailing panels are now reachable — the row scrolls — but the row does not scroll to them. When selectDefault() rings an event past the clip edge, the card below is correct while the selected panel sits outside the viewport, with the caret pinned to the edge that points at it. This is exactly the mock's behaviour, so the component is at parity; the mock simply never had a quarter large enough to show it.

Recommendation: add scrollLeftFor(layout, selectedIndex, available) to the pure module — the clamped centring offset — and assign it in the barrel's select effect, with the caret subtracting it. Deliberately not done here: it is behaviour beyond the mock, and the agreed fix was reachability. Needs 22+ events in one quarter to trigger at 320px, which no observed CERT quarter reaches.

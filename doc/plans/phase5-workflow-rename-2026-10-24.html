What changes in .github/workflows/phase5-event-runner.yml

Where it showsTodayAfter
Actions sidebar (name:)Phase 5 Event RunnerStage or replace one event's results (past-season repair)
Run title, stage modePhase 5 Event RunnerStage PEW8f-2024-2025 on cert — drafts and review report

name: "Stage or replace one event's results (past-season repair)"
run-name: "${{ inputs.commit_run_id != ''
  && format('REPLACE {0} results on {1} with staged run {2}',
            inputs.event_code, inputs.target, inputs.commit_run_id)
  || format('Stage {0} on {1} — drafts and review report',
            inputs.event_code, inputs.target) }}"
  • Both values are quoted YAML strings. A bare value containing ": " would be read as a mapping and break the file, so the stage title uses a dash, not a colon.
  • The header comment is rewritten. It currently says the runner is started by an admin "Stage event" button and a Telegram /stage command, and neither exists. The new text: started by hand only (Actions page or gh workflow run); for LOCAL work and past-season repairs; never for a current-season event, which goes through ingest-event.yml and promote.yml, because a Phase 5 commit on PROD makes promote refuse that event (python/pipeline/promotion/replay.py:162-166).

Why the titles are safe

run-name can read only the github and inputs contexts. GitHub only displays it and never runs it in a shell, so an unvalidated input in the title can't inject anything. The job still validates every input before first use, as it does today. Old runs keep their old titles: a title is fixed when the run is created.

§ 2 · left alone on purpose

What does not change

  • The file name phase5-event-runner.yml. Everything that refers to the workflow uses it: the dispatch-workflow allowlist, the handbook's workflow catalog, gh workflow run commands in plans and runbooks, the test file, and the Telegram failure message.
  • Jobs, steps, inputs, validation, secrets and permissions. The tests WF.P5.01 and WF.P5.02 already pin them and must stay green untouched.
  • The Python runner python/tools/phase5_runner.py, and the three programs that borrow its helpers.
  • Nothing else follows this workflow by its display name. Only release.yml follows another workflow by name, and it follows CI.

The FTL e-mail removal plan edits the dispatch-workflow comment that mentions this workflow. This plan doesn't touch that file, so the two plans share no files and can run in either order or in parallel.

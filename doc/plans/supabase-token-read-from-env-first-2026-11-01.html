03 · The rule

One rule, written once per language, tested as one

  1. The first SUPABASE_ACCESS_TOKEN= line of the checkout's .env, without quotes or carriage returns. This is cloud-sql.sh's reading, unchanged.
  2. Otherwise, the process environment's value.
  3. CLOUD_SQL_TOKEN_FROM_ENV=1 swaps 1 and 2.
  4. SUPABASE_TOKEN_ENV_FILE names another file to read instead of .env. This is the tests' isolation (§05).
  • python/supabase_token.py offers supabase_access_token(), standard library only.
  • scripts/supabase-token.sh is sourced, never run. It offers supabase_access_token (prints the value) and export_supabase_access_token (sets and exports it, for a script whose child processes read it, such as the supabase CLI). It uses bash builtins only, because test_schema_fingerprint runs its script with a PATH that holds nothing but stubs.

One table of 11 cases runs through both helpers (ENVTOKEN.01–02). Neither helper prints the value.

Each reader's change:

  • Python: os.environ… becomes supabase_access_token(). audit_results reads it when it queries, not at import. promote and promote_season print "SUPABASE_ACCESS_TOKEN is required" and exit 1, as gate.py and close.py already do.
  • Shell: each script sources the helper. The environment-only checks keep their wording.

04 · Every session knows it (T1 A)

A line in every session's starting context, and a test that enforces it

The SessionStart hook already adds the research rule to every session's context, on the normal path and on its failure path. TOKEN_RULE joins it on both paths:

Supabase token: read SUPABASE_ACCESS_TOKEN only through python/supabase_token.py
(Python) or scripts/supabase-token.sh (shell); both take .env before the environment.
Never os.environ for it (ENVTOKEN.05-06 fail preflight). A tool that reads the
variable itself (the supabase CLI): source scripts/supabase-token.sh &&
export_supabase_access_token first, in the same command. A 401 means that token was
rejected; never report the environment's copy.

Test ENVTOKEN.09 (test_session_start.py) fails if the hook's context, on either path, does not name both helpers. Sessions I start are sessions in this repository, so they get the same line. Their briefs name the helpers as well.

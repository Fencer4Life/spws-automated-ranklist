The organizer download page — agreed design

One protected page on weteraniszermierki.pl that lists every event with open entries, and hands its organizer a complete, correctly named set of Fencing Time files with an eight-step instruction beside them.

1 · Why this is being rebuilt

The first version of this page rendered plan §9’s file list and skipped plan §9’s manual. A four-word table column — „Co z tym zrobić” → „Importuj jako zawody” — stood in for an eight-step tutorial. The Polish read like a translation. The language flags that were asked for were never built; only a lang attribute existed. The page was wired to one event while two have live entries.

Three further defects surfaced during review, and each is fixed here rather than documented:

Found during review

Files were built on page load, not on download. The page fetched once, generated all XML into memory, and the button only serialised what was already there. Open at 08:00, press at 10:00, and you silently received the 08:00 entry list. The copy („powstają na bieżąco”) concealed this rather than stating it.

127.0.0.1 was refused because Vite binds IPv6 loopback only. Fixed (--host in .claude/launch.json); recorded so it is not reintroduced.

The tutorial’s step 6 pointed at a file we do not generate — the fencer-database pick-list. That is the step which prevents duplicate fencer records, so it is the step that matters most. It is built here.

3 · Access — the capability link

ADR-090 §3 settled that administration stays on GitHub Pages and that a sign-in modal is not reachable from a public page on the association’s site. A login on WordPress would reverse that. So the boundary is a capability, not an identity.

It is worth being precise about what is being protected. Every name, gender, weapon and age category on this page is already public through vw_registration_entry_list. Birth years, fencer ids and edit tokens are not on it and never were. The token therefore does not defend a secret; it keeps an organizer-only tool from sitting in front of four hundred fencers, and it gives us something to rotate if a link goes astray.

tbl_ftl_export_token (uuid_token PK, txt_label, ts_created, ts_revoked)

fn_ftl_export_events(p_token UUID)
fn_ftl_export_entries(p_id_event INT, p_token UUID)
fn_ftl_roster(p_id_event INT, p_weapon enum_weapon_type, p_token UUID)

An absent, unknown or revoked token returns no rows rather than an error: a stale link should look empty, not broken. Both functions stay anon-callable and SECURITY DEFINER — the check moves inside them, which is what makes this a boundary rather than a curtain. Revocation is one statement.

Known weakness, accepted

A capability URL travels in browser history and in the Referer header. Rotation is the answer, and the page sets referrerpolicy="no-referrer" on outbound links. This degrades later into a per-organizer token — the table gains an organizer column and the URL shape does not change — but that would stop it being an aggregate page, which is what was asked for.

4 · The page

Event cards

fn_ftl_export_events returns id, code, name, city, start date and entry count for every event with at least one registration whose end date has not passed — today, exactly two. Each renders as a card showing code, name, city, date and „n zapisanych”. Clicking one selects it. The event attribute preselects a code when present; otherwise the soonest event wins. The card row is hidden when only one event qualifies.

Header

{name} {CITY} {code} — I Puchar Polski Weteranów w Szermierce OPOLE PPW1-2026-2027. The city is uppercased for scanning; txt_location now arrives with the picker row, which removes the second vw_calendar round trip the element used to make.

Per-weapon accordion

Three collapsed rows instead of twenty-eight open ones. Each header states the weapon, a summary („eliminacje mix + 9 tabel DE + baza zawodników (181)”) and a file count, so the set can be read without expanding anything. Inside, the existing table: filename, in-file title, fencer count, what to do, download. Roster rows are amber and say NIE wczytuj jako zawody.

Generation happens on download

The manifest is still derived on load, because the table must show something. The two download paths become asynchronous: re-query fn_ftl_export_entries, rebuild, then hand over. One call, measured at ~30 ms for all 43 PPW1 registrations. The page shows which moment the list it is holding reflects, and the copy says plainly that files are made when you press the button.

Language

Two flag buttons top-right, matching LangToggle.svelte’s markup but restyled for the dark card. Polish is the default and stays the default; the lang attribute sets the initial value and a click overrides it. No persistence — this is an embed on a CMS page, not an application.

5 · The instruction

Eight numbered steps, both languages, rendered on the page and written into the archive. Menu paths appear as they read in Fencing Time, because the software is in English; page numbers cite the Fencing Time 4.7 User’s Guide.

  1. Pobierz pliki i rozpakuj archiwum — on the machine that runs Fencing Time.
  2. Wczytaj zawody — File → Import → Import Events (p. 22). POOLS-MIXED first, one per weapon, then the DE files.
  3. Połącz tabele eliminacji — Combine Events (p. 22). The split is maximal by design; we re-split results by birth year regardless.
  4. Nie usuwaj cyfry z nazwiska — PRZYKŁADOWSKA (1) Anna means V1, and that digit is how results are read back.
The example name is invented, deliberately

The first draft illustrated the marker with KAMIŃSKA (1) Gabriela — who is a real fencer, entered for a live event. This page is published on the association’s public site, so the example is now PRZYKŁADOWSKA (1) Anna, which matches nobody in tbl_fencer or tbl_registration and reads to a Polish speaker as „Example”. Kowalski, Kowalska and Nowak were all checked and rejected: in an association this size the stock placeholders are real members.

The real name stays where it is evidence rather than copy — seed data, staging diffs, ADR-065 and ADR-080, and the code comments explaining what the scraper actually reads. One consequence to carry into the build: frontend/tests/FtlExport.test.ts asserts the old string and must be updated with the copy.

  1. Rano odśwież listę startową — Summary → Re-Import Competitors from XML File (p. 144). Rounds and entered scores survive.
  2. Ktoś przyszedł bez zapisów — Event Competitors → Import from XML (p. 145), tick that one person. Never type the name: a typed name returns as a new person and creates a ranking duplicate that cannot be merged quietly afterwards.
  3. Odeślij wyniki — nothing to do if the event is published on Fencing Time Live; otherwise send the exported results file.
  4. Kontakt — write before correcting names by hand; regenerating is faster.

Steps 2, 3, 5 and 6 are the ones that change behaviour. Step 6 is the reason the roster file is in this piece of work rather than a later one.

6 · The roster file

Three per event, one per weapon: every fencer holding any result in that weapon, full history, all nationalities, with the V-category computed for the event’s season. It is a pick-list, never a competition — its filename and its in-file title both say so, and its row on the page is amber.

Suppression follows ADR-080 amendment (e) and has two clauses, not one:

  • always suppress any id_fencer a registration for this event and weapon already points at;
  • suppress by name only when an unmatched registration bears that name and exactly one fencer does too.
The reason for the second clause

PROD holds two people called MŁYNEK Janusz — #197, born 1951, with nineteen results, and #356, born 1984, with none. The naive rule („exclude anyone whose name matches a registration”) would hide the nineteen-result Janusz from the roster because a different Janusz entered — and he is precisely the person an organizer might need to tick in.

Measured on the PROD mirror today: 206 épée fencers, 76 foil, 102 sabre. After suppression for PPW1: 181 / 68 / 89. The event’s set goes from 25 files to 28.

7 · Build order

Starting state — the tree is mid-edit

Work was stopped part-way. Already on disk: both locale files rewritten with the corrected wording and all eight steps (610 keys, PL/EN in sync); 20260912000004_ftl_export_entries.sql extended with fn_ftl_export_events() and applied to LOCAL. FtlExport.svelte is untouched and still references two deleted keys, so frontend/tests/FtlExport.test.ts is red: 3 failed, 7 passed. That is the starting point, not a regression to hunt.

  1. Token — tbl_ftl_export_token, the three RPC signatures, deny-by-silence, pgTAP.
  2. Scope — fn_ftl_export_events drops the seven-day grace: COALESCE(dt_end, dt_start) >= CURRENT_DATE.
  3. Roster — fn_ftl_roster with both suppression clauses and the MŁYNEK fixture; ROSTER wired into both generators (roster_scope / roster_title already exist in each).
  4. Archive — instructions and manifest written into the zip, both languages.
  5. Page — event cards, header, accordion, flags, generate-on-download, the eight steps.
  6. Element — reads k from the URL, fetches the event list, drops fetchEventForRegistration.
  7. Documentation — ADR-080 amendment (g) gains the token, the picker, the accordion and generate-on-download; RTM FR-136 likewise; ADR-090 gains the capability-link pattern; the handbook’s registration-lifecycle page gains the picker sentence.

9 · Deliberately not in this

  • Club harvesting (plan step 6) and the reconciliation report (step 4).
  • The standalone PL/EN manual document and the WordPress publish (step 10). Until that page exists the surface is reachable at register.html?view=export&k=<uuid>, which carries the same credential injection.
  • A print stylesheet — raised, not decided. The instructions inside the archive cover the offline case that prompted it.
  • Per-organizer scoping — the token table is shaped to allow it later.
  • ts_ftl_sent — a self-service download does not stamp, so the deadline e-mail may still reach someone who already has the files. Accepted for now.

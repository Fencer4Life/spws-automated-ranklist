03 · Found while capturing

Two problems fixed before this sheet

  • P1 · On a phone the „Usuń” button was clipped at the card's edge. Its cell kept the desktop width rule (1 %), so it measured 3 px and the button spilled out. The phone layout now gives that cell its own width. Visitors never have that cell.
  • P2 · After a removal far down the list the done line was out of view, and focus fell to the page when the confirmation closed. Focus now moves to the done line, which brings it into view (ELREM.05 extended, seen red first).
  • From the tests: CV.15 found that signing out left an open confirmation on screen; it now closes with the buttons.

04 · Checked, nothing to fix

The WordPress calendar

The WordPress calendar element mounts the same application as the admin app, so the new setting reaches its code path. It cannot become true there: the application resets the sign-in on load and opens a sign-in only on github.io or on the page carrying admin-entry (/ranking/). The existing test WP.ADM.01 (frontend/tests/SiteChrome.test.ts) pins that the calendar page ignores ?admin=1.

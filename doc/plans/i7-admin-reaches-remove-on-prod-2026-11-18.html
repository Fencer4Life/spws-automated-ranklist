02 · Already in the code

The pattern exists for one menu item

  • „Ranking” already stays on the page when you are signed in. followSiteLink (Sidebar.svelte:151–159) cancels the link and switches the view in place, so the reload does not end the session. Test: Sidebar.test.ts:337 (WP.NAV.01).
  • The app can already show the calendar on any element. navigateTo('calendar') loads the calendar data (App.svelte:985–995), and CalendarView already receives isAdmin, so the entry list then shows „Usuń”.
  • The two WordPress page bodies style the page identically. doc/wordpress/ranking.html and znajdz-zawody.html differ only in their comment and their element.
  • But the Ranking element has no height of its own. The calendar is built from geometry and needs real height. CalendarElement.svelte gives its host height: 100dvh, and .site-fill fills that host with height: 100% (App.svelte:1753–1763). RanklistElement.svelte has no such rule, so a calendar shown inside it would collapse. The fix must give the calendar its height there (part B).

03 · The fix

Two small parts

A · THE MENUSidebar.svelte · followSiteLink

When you are signed in, „Znajdź zawody” opens the calendar on the same page, the way „Ranking” already does: it cancels the link and calls onnavigate('calendar'). While the calendar is shown, „Znajdź zawody” is marked as the current page and „Ranking” brings the list back. Signed out, both remain ordinary links.

B · THE HEIGHTApp.svelte · one class, one rule

When the calendar is opened on an element that did not start on it (the Ranking page), .ranklist-app gets a class that sets height: 100dvh. The calendar page's own element starts on the calendar, never gets the class, and keeps today's rules exactly. Its pixels are proven unchanged in §05.

What does not change

  • Visitors: every menu item on every WordPress page is the same link as today.
  • „Kalkulator punktów” and „Tabela punktacji”: still separate pages, and following them still ends the session. Not asked for, not touched.
  • The GitHub Pages app: still CERT, with „Usuń” working on CERT's copy.
  • The entry list, the confirmation, the database, the WordPress page bodies: nothing changes. No WordPress republish is needed, because the change ships in the bundle.
  • The address bar stays /ranking/?admin=1. Reloading brings back the sign-in and the Ranking list, as today.

08 · Your decisions

Three questions

Q1 · Signing out while the calendar is open on the Ranking page

The „Usuń” buttons and any open confirmation disappear at once (already pinned by CV.15). The question is which screen you then see.

Recommended: stay on the calendar, as a visitor. Nothing jumps under you, and the calendar is a public screen anyway. The alternative is to return to the Ranking list.

Q2 · The ADR-090 amendment text

Proposed, added as a dated amendment of 2026-11-18:

„On /ranking/, while an administrator is signed in, the drawer's calendar entry opens the calendar in place instead of following its link, as the Ranking entry already returns to the list in place, because following a link mounts the app afresh and ends the session. The calculator and the points table remain links. Signed out, every entry is a same-tab link.”

Recommended: accept as written.

Q3 · The final proof on PROD

I cannot sign in on PROD: entering the password is yours. After release I check the visitor's view myself. Then you would sign in on weteraniszermierki.pl/ranking/?admin=1, choose „Znajdź zawody”, open any entry list, and confirm „Usuń” is there. To see the confirmation, press „Usuń” and then „Anuluj”, so nothing is deleted.

Recommended: yes, a two-minute check by you right after the release.

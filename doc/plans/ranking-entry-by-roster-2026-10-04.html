Ranking · 2026/27 · Plan

Ranking entry by roster: everyone in the database with points in the window

Your rule: from 2026/27 a fencer enters the fencer table only through a PPW or MPW start, and anyone in it with points in the rolling window appears in the ranking, EVF+ points included. The change is small. It needs no schema change and no change to the ranking functions. One governed setting changes through the audited revision procedure, then tests and documentation follow, in one release.

Approved 4 Oct: A, A, A, A, reason as proposed ADR-110 signed off; done on CERT (rev. 8) and PROD (rev. 10) Released 4 Oct: main 675582d9, CI and Release green, PROD approved +19 fencers in the 2026/27 ranking, none removed no migration

04 · Decide this first

Five decisions

D1 · What does “the rolling window determining entry” govern for the fencer table?

OptionEffect
A · The window decides which points count; intake stays as it is recommendedA fencer is in the table after one PPW or MPW start, at any time (ADR-106 today). The ranking counts their points from the ranked season and the one before. KOŃCZYŁO appears now, and his EVF results this season are stored and count.
B · EVF results are stored only for a fencer with a PPW/MPW start inside the windowADR-106 is tightened, with a change to the admission module and its tests. KOŃCZYŁO’s 2026/27 EVF results would be refused until his next PPW start. Only his 2025/26 points would show, which works against your aim.

D2 · The three fencers in the window with no PPW/MPW start (GOLA, KOSZYK, SZUMIELEWICZ)

OptionEffect
A · Rank them: they are in the database recommended“All fencers in the DB are in the ranking”, literally. No extra work.
B · Rank only fencers with a PPW/MPW start in any seasonThe ranking enforces the table rule even for legacy rows. This needs a migration of both ranking bodies (the gate reads fn_spws_starter_ids()), so the plan grows by one migration and its tests.
C · Review the three and remove whatever should not be in the databaseA data clean-up, with your sign-off per fencer.

D3 · The gate itself (entry_types in SQL, the Admin validator, the rules window)

OptionEffect
A · Keep it, unused recommendedNo code change. A future season could use it again by setting entry_types, and its tests stay on a test season.
B · Remove itCleaner, but larger: two SQL functions, the validator, the rules window, the type and their tests.

D4 · The public season-rules window

OptionEffect
A · No new line recommendedThe “who enters” line disappears with entry_types; the bucket rows already say what counts.
B · A new line, e.g. „W rankingu jest każdy zawodnik SPWS, który ma punkty w okresie rankingu.”I draft it in Polish, you approve the wording, and it gets one frontend test.

D5 · What the audit record says

The revision records an actor, a reason and an optional board-decision reference. I propose reason “ADR-110: ranking entry by roster (decision of 4 Oct 2026)”, with a board reference only if you have one, for example a resolution number.

06 · Pre-mortem

What could go wrong, and what the plan does

Could go wrongThe plan
The revision rescores every scored 2026/27 tournament and one failsThe procedure is one transaction and rolls back whole on any failure. The multipliers are unchanged, so the scores come out identical. LOCAL proves it first.
CERT and PROD stop matching for promoteThe result fingerprint leaves out the revision id and every timestamp (checked in fn_event_result_document), so an unchanged rescore keeps it equal.
It runs while a promote, ingest or drain is writingRun it only when none is running: those hold prod-write and cert-write, and a direct SQL call does not.
Tests break when the seed changesThe ranking tests stop reading the live rules (step 2). The single test that pins the live rules changes in the same commit as the new seed (step 6).
Fencers ask why a name with no SPWS points leads a rankingThat is the rule. If you want it said on the page, choose D4 B.

ADR-110 draft

Signed off 4 Oct and written to doc/adr/110-ranking-entry-by-roster.md (status Accepted). The draft below is kept as you signed it.

ADR-110: From 2026/2027 the fencer table is the ranking entry; everyone in it with points in the window is ranked

Status: Draft (proposed 2026-10-04; awaiting sign-off). Supersedes: ADR-103 §6, ranking entry through PPW or MPW (FR-141); the gate mechanism stays, unused. Relates to: ADR-106 and ADR-020 (who enters the fencer table), ADR-100, ADR-097 (the audited revision), ADR-091 and ADR-108 (carry-over).

Context. Under ADR-103 §6 a 2026/27 fencer was ranked only with a PPW or MPW result in the ranking’s window. On 4 Oct 2026 this left out KOŃCZYŁO Tomasz, whose last PPW/MPW start was in 2024/25 and who fenced only PEW in 2025/26. The user set the rule: the fencer table is the gate, and the ranking shows everyone in it with points in the window.

Decision.

  1. A fencer enters the fencer table only through a PPW or MPW result (ADR-020). International results (ADR-106) and PZSz results (ADR-100) never create one, and neither does a registration. This is unchanged and recorded here as the rule.
  2. The 2026/27 ranking ranks everyone in the fencer table with points in its window: the SPWS-2026-2027 rules carry no entry_types. The window and the buckets are unchanged.
  3. Fencers created before ADR-106 without a PPW/MPW start are ranked like everyone else when they have points in the window.
  4. The gate stays, unused: fn_ranking_full still honours entry_types, and the season-rules window shows its line only when it is set. No new public text.
  5. The change goes through fn_revise_and_rescore_season on CERT and PROD, with the reason “ADR-110: ranking entry by roster (decision of 4 Oct 2026)” and no board reference. Scores do not change, and the result fingerprint ignores revision ids and timestamps, so promote’s comparison holds.
  6. seed_post_backfill.sql stops re-applying the old rules.

Alternatives rejected.

  • Keep §6: it leaves out SPWS fencers with EVF+ points.
  • Gate intake by the window: it refuses results the rule wants counted.
  • Rank only fencers with a PPW/MPW start in any season: a migration, and not the table as it stands.
  • Remove the gate: larger.
  • A direct UPDATE: it bypasses ADR-097’s audit.

Consequences. The rolling 2026/27 ranking grows from 227 to 250 rows (188 to 207 fencers), with nobody removed and no total changed. SE27.RANK.01–05 set entry_types themselves, ROSTER.01–04 are new, and ADM27.RULES.14 pins the new rules. FR-141 is superseded by FR-152. Each environment gets one revision row, and the seed carries the new rules.

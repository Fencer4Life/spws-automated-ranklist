03Access — what works and what is a dead end

Use this XML-RPC at https://weteraniszermierki.pl/xmlrpc.php, authenticating with WP_USER + WP_APP_PASSWORD passed as the first two params of the method call. Verified working for wp.getUsersBlogs, wp.getPost, wp.getPosts, wp.getTerms. nav_menu_item is an ordinary post type, so wp.newPost creates menu items too.
Do not burn time here The REST API cannot authenticate. The host is LiteSpeed and it strips the Authorization header before WordPress runs. This was proven, not guessed: a deliberately wrong password returns the byte-identical rest_not_logged_in error as the correct one. ?rest_route= does not help either. It is fixed only by an .htaccess rule, which needs a DirectAdmin login nobody has yet. Do not debug this. Use XML-RPC.

Three traps that already cost time

  1. The username is Olek. „AutomatRanklista” is the label given to the application password, not a user. Authenticating as AutomatRanklista fails with „Błędna nazwa lub hasło” and looks exactly like a bad password.
  2. The host 403s Python's default User-Agent. urllib out of the box gets HTTP 403 Forbidden from xmlrpc.php. Send a normal browser-ish User-Agent header and it works. curl is unaffected.
  3. The application password contains spaces. It is stored quoted in .env. Load it with set -a; . ./.env; set +a — an unquoted value breaks shell sourcing mid-line.

Working snippet

cd /Users/aleks/coding/SPWSranklist
set -a; . ./.env; set +a
python3 - <<'PY'
import os, urllib.request
u, p = os.environ['WP_USER'], os.environ['WP_APP_PASSWORD']
body = f"""<?xml version="1.0"?><methodCall><methodName>wp.getUsersBlogs</methodName><params>
<param><value><string>{u}</string></value></param>
<param><value><string>{p}</string></value></param></params></methodCall>"""
r = urllib.request.Request(os.environ['WP_URL'] + '/xmlrpc.php', data=body.encode(),
    headers={'Content-Type': 'text/xml', 'User-Agent': 'Mozilla/5.0 spws-deploy/1.0'})
print(urllib.request.urlopen(r, timeout=20).read().decode()[:400])
PY

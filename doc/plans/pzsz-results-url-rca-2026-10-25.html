03 · Your rule, 25 Oct

URL wyników stays empty until the Admin UI populates it

Calendar automation writes only URL komunikatu, and only with the organizer's letter, under the same fill rules as before. Your 9 Aug hand move on CERT, the calendar page into URL komunikatu, stays as it is. The scrapers do not repeat it, for two reasons:

  • The PZSz letter passes read URL komunikatu as the letter to download.
  • The EVF refresh and the mirror fill URL komunikatu only while it is empty.

A calendar page there would be read as the letter and would block the real one. The PZSz page is never lost: it can always be rebuilt from id_pzsz_event.

Results links still reach the database from three places, all supplied by a person:

  • Admin (fn_create_event, fn_update_event);
  • the url_event input of ingest-event.yml;
  • promote, which copies the CERT run's link to an empty PROD slot.

09 · Signed off 25 Oct (S1 A) · now doc/adr/117-results-links-admin-only.md

ADR-117: results links are set in Admin only; calendar automation writes only the organizer's letter

Context

url_event … url_event_5 serve three purposes:

  • the calendar card's “Wyniki” link;
  • the domestic and PZSz ingest's FTL schedule;
  • the EVF/FIE ingest's list of sources.

A calendar page written there by automation sent fencers and the ingest to the wrong place three times:

  • EVF before the event, until 26 Jul (ADR-039 rev 4);
  • EVF again, refilled within the hour of the cleanup on 26 Jul and still on PROD;
  • PZSz from creation, since 3 Sep.

ADR-039 rev 4's date gate still wrote the page once the event had ended, and its cleanup ran before its code was deployed.

Decision

  1. No calendar automation writes a results slot, before or after the event. That covers the EVF sync (create, reuse, refresh, date heal), the PZSz sync and the CERT→PROD calendar mirror, in both the Python payloads and the SQL functions.
  2. Calendar automation writes the organizer's letter to url_invitation under the existing fill rules, and no calendar page.
  3. Results slots are filled in Admin. The results pipeline carries an operator-supplied link: the url_event input of ingest-event.yml, and promote's fill of an empty PROD slot from the CERT run. Both are unchanged.
  4. A one-time clean-up, fn_clear_calendar_results_links() (§04 rules), shipped in the same migration as the function changes so it cannot run before the fix.
  5. The PZSz “Send ingest” notice fires when an administrator has set url_event.

Alternatives

  • A date gate (ADR-039 rev 4): rejected. A calendar page never holds results, and the gate refilled the cleaned data.
  • The calendar page as a URL komunikatu placeholder: rejected. The letter passes would read it as the letter, and fill-blank rules would block the real letter.
  • A database CHECK on the page patterns: not now. The seed loads after the migrations, and a pattern cannot express “Admin only”. The tests and the functions are the guard.

Consequences

  • An EVF event without an Admin link is ingested from EVF's own results.
  • The calendar card shows no “Wyniki” link until Admin fills one.
  • A CERT ingest needs the link on CERT (O1, D2).
  • Supersedes the url_event rule of ADR-039 rev 4. Amends ADR-040 (the refresh and the mirror no longer fill slots 2–5), ADR-087/ADR-116 (the PZSz create and R5) and the lifecycle page's admin-enrichment tier.
  • Tests: CALURL.01–15.

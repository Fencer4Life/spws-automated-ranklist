What is live

Two features, five migrations, both tiers

The registration identity block (ADR-093)

A fencer entering a name that nearly matches an existing record is no longer silently attached to it or silently ignored. fn_registration_identity_candidates classifies every same-name candidate and the form resolves a six-rung ladder; fn_confirm_registration_identity records the answer against the row's uuid_edit_token.

A CONFIRMED birth year can no longer be overwritten from the public path at all. It becomes a PENDING proposal an administrator applies or rejects in the birth-year review tab, and the recompute drain announces each one over Telegram. The reason is in the ADR: ADOPT_DECLARED was a parameter, not a click — the server could not tell a fencer pressing a button from a crafted RPC call, so the capability was removed rather than narrowed.

The FTL export page (ADR-080 amendment)

An organizer downloads their own seed files from a public page instead of asking for them by e-mail. Event cards for every live event, a per-weapon accordion, an eight-step import instruction in Polish and English on the page and inside the archive, and a dependency-free stored-ZIP writer because a browser will not start twenty-eight downloads.

Files are built when Download is pressed, not at page load — both paths re-read the entry list first, and the page shows the moment its list was taken. fn_ftl_roster adds the pick-list that stops an unannounced fencer being typed in as a duplicate identity.

What went wrong, and the fix that outlives it

A copied gate list turned one push into four

The plan's Verification section listed pytest, vitest, pgTAP, svelte-check, postgrestools and check_docs.py. It omitted basedpyright, ruff, check-coherence.sh, check-spec-sync.sh, and the deploy-time posture check. Every one of the omissions failed — but serially, each discovered from a red run after a push, and a push to main auto-deploys PROD.

✓ The definition of done is now one command

scripts/preflight.sh — fourteen gates, every CI check plus the AGENTS.md gates CI does not run plus the git diff --check that blocks integration. It runs all of them to completion even after one fails and prints a pass/fail line each, so a plan learns everything wrong with it in one pass. doc/claude/planning.md rule 5a forbids a plan from enumerating its own gate list.

scripts/check-anon-allowlist-sync.sh closes the specific trap that broke the first release: the anon-EXECUTE allowlist lives in two files — pgTAP 52.7 and check-security-posture.sh — and pgTAP only ever reads one of them, so a drift stays green through all of CI and fails at deploy. Add a function to 52.7 and you must add it to the other file in the same change.

Two gates remain outside preflight because they are per-change, not global: postgrestools check <path> for touched SQL, and scripts/refresh-graph.sh before committing.

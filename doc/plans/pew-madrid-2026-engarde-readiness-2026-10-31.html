03 · Issues found, numbered

One blocker, two latent faults, three housekeeping items

#1 Blocker: "EPEE MALE 2" is marked sabre in Engarde

Engarde numbers the competitions in order: 5912E1 EPEE MALE 1, 5912E3 EPEE MALE 2, 5912E4 EPEE MALE 3-4. EPEE MALE 2 starts at 09:00 with the other épée pools, but the organiser set it to arme="s" (sabre). parse_competition_list takes the weapon from arme, so:

  • while TABLE SABRE MALE 2 is still running, men's épée V2 results are stored as SABRE M V2;
  • once TABLE SABRE MALE 2 is completed (it starts at 17:00), the ingest refuses the whole event ("two sources for one bracket SABRE/M/V2") and writes nothing.

It is new: none of the 7 earlier Engarde tournaments we ingested has a title that disagrees with arme.

#2 A title with three or four categories is read as two

"FOIL MALE 1-2-3-4" reads as V1, V2 and "SABRE FEMALE 1-2-3" as V1, V2. Both are skipped either way, but the staging report gives the wrong categories as the reason.

#3 A running Engarde final does not keep the event open

The lifecycle (ADR-108 §7) counts only FTL's "not final" skip. A running Engarde final is skipped as "not completed (…)", which the rule ignores. If the organiser never marks one TABLE as completed, an ingest after 1 Nov, or the daily close, could set Madrid to COMPLETED with that bracket never read. Not an issue today; it matters from 2 Nov.

#4 PROD's PPS1e ingest sources are stale (mine, 26 Oct)

CERT's json_ingest_sources says both listings were committed. PROD's still says women's épée was "dropped, not final". The close completed PROD without refreshing it, and the reconciler reports the difference every day.

#5 Revision 5 of the RCA plan page is missing from main and from the docs index

Its 4 commits exist only on claude/pzsz-url-event-rca. When this worktree moved to main, the index dropped the newer chunks.

#6 The ingest-event.yml input description is wrong for EVF events

It says any url_event other than an FTL schedule "is refused (ADR-117)". That is true only for SPWS and PZSz events; an EVF event accepts an Engarde, 4fence or Ophardt link.

#7 Observation: the invitation letters differ (M6)

CERT: …/2026/10/Madrid_invitation-letter2026-V1.pdf. PROD: …/2026/08/Madrid_invitation-letter2026.pdf. The reconciler leaves it by policy and lists it under "Divergences NOT synced". You want PROD to follow CERT's newer letter instead (31 Oct). The plan is cert-event-details-reach-prod-every-scraper-2026-10-31.html, and Skopje (V3 on CERT, V2 on PROD) is covered too.

04 · The fix (M1 A) — Python only, no migration

What would change

UPDATEpython/scrapers/engarde.py
  • #1 The weapon comes from the title when the title names exactly one weapon (épée / foil / sabre words in EN, FR, ES, IT, PL, DE, HU, accents folded). Otherwise it comes from arme. This is the rule gender already follows, because sexe is wrong at some organisers. competition_list_facts uses the same weapon.
  • #2 parse_engarde_category reads a whole chain ("1-2-3-4" → V1–V4) where it read only the first pair.
  • #3 The reasons that never change come first: team event, pool round, no category, spans categories. Only a single-category final that is not completed is skipped as not final (Engarde lists it as <state>).
UPDATEpython/pipeline/promotion/lifecycle.py · run_record.py
  • #3 A skip whose reason starts with "not final" is a listing that is not final yet. event_status and the run record's last day use that test. FTL's NOT_FINAL text is unchanged, so no recorded run's schedule hash changes. No IN_PROGRESS event reads Engarde today: every Engarde event on CERT is COMPLETED.
UPDATE.github/workflows/ingest-event.yml
  • #6 The input description says what each route accepts.

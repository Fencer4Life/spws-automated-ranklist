When the daily close needs to look at past seasons

Every morning, the daily close now checks past seasons for open events. It can only find one on three occasions: when a season ends, when we re-ingest an old event ourselves, or when someone changes a status by hand. Checking every day is waste. This page proposes checking only when something can be there. It also fixes a fault I released today: the database test fails the day after every season ends.

01 · Why it runs daily

No reason of its own

I added the pass to the daily close (event-close.yml, 04:17 UTC) because that job already ran every morning. I never asked when the pass could find anything. Each run costs one read query on CERT and one on PROD. It sends nothing to FTL and posts nothing when there is nothing. It is cheap, but it searches every morning for something that is almost never there.

03 · The fault in what I released

pgTAP 128 reads PROD’s exported seed, not PROD itself

CI and LOCAL load supabase/seed_prod_latest.sql (supabase/config.toml, [db.seed]). That file is PROD’s last export. The export runs after a promote or when started by hand; the close never runs it.

On 16 Jul 2027, every event still open in the committed seed belongs to a season that has ended. Test 128.1 then fails in CI and in preflight. The pass completes those events on PROD that morning, but the committed seed still holds them open. Every push stays red until someone exports the seed again. Today’s run passed only because the last export, after Napoli’s promote, came after IMSW and PEW1f were completed by hand.

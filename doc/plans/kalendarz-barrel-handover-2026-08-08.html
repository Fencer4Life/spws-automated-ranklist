01What the design is

The calendar's month-grouped event list, the flat rolling-progress strip and the season dropdown are all removed. In their place: a rotating three-row quarter barrel that is the primary control, driving a single full-detail event card beneath it.

The original complaint was that the progress strip encoded two variables in one visual channel — hue for event type, lightness of that same hue for completion — so neither read cleanly. The redesign gives each variable its own channel: hue for type, fill for completed, a ring for the next upcoming event.

02Settled — do not relitigate

Each of these was decided explicitly during the session, several after being tried and rejected in another form.

  • Three-row drum. Focused quarter centred, previous receded above at rotateX(46deg), next below at -46deg. Rotation is translateY on the drum; facing angle is rotateX per row. The DOM never re-renders on rotate — only classes change.
  • Detail tiers follow rotation. Focused row shows day, month, code (and city on the selected panel). Receded rows drop to day + code at 38px.
  • Engraved seams. Quarter label (4Q26) at 11px muted on a hairline above each row, rotating with it. Season code (25/26) at the seam's right end on the focused row, and permanently on season-boundary seams, which take a 2px stronger rule.
  • Continuous history, no season clamp. The drum rolls back to the start of history. Crossing a boundary drives season state — the barrel owns it, which is why the dropdown could go.
  • Whole row is the tap target. Tapping a receded row rotates it to centre; tapping a panel on the focused row selects that event.
  • Overlap, not shrink. When a quarter's panels do not fit, they fan and overlap at full size rather than compressing. z-index = 200 − |i − selected| × 2, so the stack peaks on the selection: panels to its left expose their left edge, panels to its right expose their right edge. Positions are fixed at i × S; only z-index changes on select. Step S = (available − W_selected) ÷ (n − 1), floor 13px.
  • Selected panel widens to 78px to carry the city, 48px when the event has no city. Uniform negative margins mean every panel after it shifts right automatically — no special-casing.
  • Panels keep the date. Day and month on every panel, always.
  • EVF codes shortened on panels to EVF + number (PEW63e → EVF63). Weapon suffix dropped — it bought nothing once the weapon filter went. Full code preserved on the card.
  • No weapon filter. Dropped entirely. The data is not to be compressed.
  • One scope control, centred below the header: PPW | +EVF.
  • Header: hamburger, SPWS wordmark, view title, EN | PL toggle.
  • Results links are labelled by day, never by weapon. One URL renders as Wyniki; several render as Dzień 1, Dzień 2. Two weapons on one day still read as that day. This follows ADR-040, which states the five URL slots are “equal-status — no role labels, no per-slot enum, no primary pointer”. An earlier per-weapon design was wrong and was removed.
  • Optional fields render only when present. Entry fee, invitation, deadline, venue, city — omitted entirely when empty. No “brak danych” placeholders.
  • Status is colour-coded via existing code. getEventDisplayStatus() in frontend/src/lib/eventStatus.ts already covers all eight lifecycle states plus derived awaiting-results. Reuse unchanged — zero new work.
  • Location is always a city, never a venue. Venue belongs in txt_venue_address. The mock never infers a city that is not literally in the string.
  • Country normalisation is a one-time enrichment pass writing ISO-3166 alpha-2 with human review of ambiguous cases — never a per-render web lookup.
  • 320px is the floor, verified throughout.

03Open questions

Recommendations given, decisions not yet made.

1. Day-label fallback for undated result URLs

Engarde encodes the date in the path (2025_09_20_pbt), so those label themselves. FTL and 4Fence may not, and ADR-040 forbids inferring day from slot position since slots are compacted and non-semantic.

Recommendation: fall back to bare numbering — Wyniki 1, Wyniki 2. Degrades honestly and fails visibly, signalling which platforms need a parser.

2. The Guildford triple — unfinished investigation

Three CERT rows — PEW63e (10 Jan, 1 tournament), PEW62efs (10–11 Jan, 9), PEW64s (11 Jan, 2) — all carry the identical url_event: fencingtimelive.com/tournaments/eventSchedule/E2A7B077F2824DD8A7F2E413B4211296. One competition, 12 tournaments, split across three event rows. The next year's Guildford (PEW6efs-2026-2027) is correctly a single row with 12 tournaments. All three have txt_name echoing the code and txt_location null — machine-created without metadata. They sit in a 61–67 numbering block separate from that season's normal 1–9 series.

The sizing query was never completed: count how many events share a url_event with another event. Note the in-flight branches codex/fix-evf-calendar-event-codes and codex/fix-evf-calendar-event-codes-updated — this may already be known work.

3. arr_weapons — drop the default?

The column already exists (20260327000006_event_weapons.sql) with DEFAULT '{EPEE,FOIL,SABRE}' and was never populated: 102 of 103 events sit on the default. So “all three” currently means both “genuinely all three” and “nobody set this”.

Recommendation: drop the default, backfill from the lowercase code suffix, leave NULL where unknown, and add a reconciliation check flagging disagreement with ingested tournaments.

4. Location backfill scope

45 PEW events have no location; 25 of those are 2023-24 and 2024-25, which the EVF calendar may no longer retain.

Recommendation: backfill the current and previous season only (~12 events, all still scrapeable). Nobody is choosing whether to travel to a 2023 competition.

5. What the card opens on

Next upcoming, most recent result, or time-sensitive.

Recommendation: time-sensitive — the result for seven days after an event ends, then the next upcoming. The seven-day window already exists in the codebase for cancelled-event notices.

6. Scroll behaviour

Barrel pinned to the top, or the whole page scrolls.

Recommendation: scrolling. Pinning ~250px of drum on a 568px screen leaves under half the display for the card.

7. Past-season anchor

Finished seasons have no next-upcoming event, so the drum loses its focal point and rows read flat.

Recommendation: mark championships (MPW, MŚW, MEW) distinctly so past rows keep structure. Marking events the viewer competed in is better but impossible on the public embed.

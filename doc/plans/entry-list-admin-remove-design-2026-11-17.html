Entry list · Administrator · Design proposal

Removing a fencer from the entry list: an administrator's „Usuń” button

A fencer who changes plans tells the organizer; the organizer asks the administrator; the administrator removes the entry. The fencer's side gets no new control. This page proposes where the button lives and how it behaves. Nothing is built.

Design signed 17 Nov 2026 · Q1 yes · Q2 no · Q3 no no code written

01 · The plan in one paragraph

What I propose

The administrator already opens the same „Lista zgłoszonych” that fencers see, from the calendar card in the admin application. While signed in, each row of that list shows a „Usuń” button. Tapping it asks for confirmation with the fencer's name and the event; confirming deletes the entry, the row disappears and the tiles count down. Visitors who are not signed in see the list exactly as it is today.

The search and filters released today are what make this the right place: the administrator types „zak”, sees one row, removes it.

03 · Why here

Two other places I considered

  • In the event editor (Wydarzenia → „Rejestracja SPWS”). It would need a second list of entrants built from nothing, without the search and filters. More work for a worse tool.
  • A command to the Telegram bot („usuń PEW5 Żak Anna”). Handy on a phone, but two people can share a name, a typo removes nobody or the wrong person, and there is no list to look at before confirming. The admin application already works on a phone.

04 · How it works

Behaviour and rules

  • Only a signed-in administrator can remove. The database already says so: the registration table lets administrators delete and refuses everyone else. The button is hidden for visitors, and a visitor who forged the request would be refused by the database, not merely by the page. The plan's first step proves this with a test on LOCAL before anything else is written.
  • The public pages do not change. The public registration page and the WordPress calendar have no sign-in, so the button can never appear there.
  • The entry is deleted, not marked. It leaves the public list and the organizer's start files, which are built from the list at download time.
  • It works until the event starts, also after the registration deadline. After the deadline the fencer cannot sign up again; the confirmation text then says so instead of „może zgłosić się ponownie przed końcem terminu zapisów”.
  • The administrator must be looking at PROD. Real entries live on PROD; the admin application's CERT/PROD switch decides which list is shown, as for every other admin action.
  • If the delete fails (connection lost, session expired), the row stays and a message says the entry was not removed.

05 · Decided

Your answers, 17 Nov 2026

  1. Q1 · The button lives on the entry list, for a signed-in administrator: yes.
  2. Q2 · A line under the public list telling fencers how to withdraw: no. We do not want to encourage people to resign; the public list gets no new text.
  3. Q3 · A trace of removals: no.

The confirmation text is as you worded it: „Tej operacji nie można cofnąć. Zawodniczka może zgłosić się ponownie przed końcem terminu zapisów.”
